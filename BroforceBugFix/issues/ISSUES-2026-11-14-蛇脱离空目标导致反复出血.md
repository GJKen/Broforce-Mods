# 蛇脱离空目标导致反复出血

2026-11-14，用户发现联机地图右侧大量喷血，并要求区分原版缺陷与联机同步责任。已确认脱离空目标时抛异常属于原版通用缺陷，修复独立放入 BroforceBugFix；最初双向引用丢失的触发因素尚未确认，不能据此排除联机影响。

## 现场与源码

FRP Direct 双端，Workshop `3642518573` / `Contra Predator II` / `Test Evan2`，SID 109。右侧 `(882,126)` 的死亡 `MookTrooper`（`109|0|20399|3`）仍持有 `inseminatorUnit`，对应蛇（`AlienFaceHugger` / `ZSnake`，`109|0|20661|3`）的 `inseminatedUnit` 已为空，敌兵计时超过 220 秒、health=0。

原版源码：

- `AlienFaceHugger.cs` 的 `DisconnectFaceHugger` 在蛇仍活着且 `dieAfterInsemination=false` 时直接调用 `inseminatedUnit.IsFlexing()`，没有处理空目标。
- `TestVanDammeAnim.cs` 的 `DisConnectFaceHugger` 先调用蛇的脱离方法，再清除敌兵的 `inseminatorUnit`；异常使清除语句无法执行。
- 敌兵 Update 继续进入感染计时/伤害/死亡逻辑，逐帧出血并再次触发相同异常。日志堆栈含 `AlienFaceHugger.DisconnectFaceHugger` → `TestVanDammeAnim.DisConnectFaceHugger` → `TestVanDammeAnim.Update` → `Mook.Update` → `MookTrooper.Update`。

3 秒探针在房主记录 `CreateBloodParticles(882,132)` 共 542 次，包含两层重载，约 271 次实际死亡出血；加入方记录 562 次，调用来自 CMM 的 `ReceiveWorldHitEffectRPC`，即正常转播房主持续产生的血。原现场的蛇后来被战斗消灭，循环停止；这不算补丁验收。

现场还存在自定义角色 Drunken Broster 的脱离 postfix，检查其 IL 后只见读取蛇的 GameObject 名称，没有访问空目标，未归咎或修改该角色。

## 修复边界

`src/FaceHuggerDetachFix.cs` 使用独立 Harmony ID `GJKen.BroforceBugFix.FaceHuggerDetach`。Transpiler 只替换 `Unit.IsFlexing` 调用，判断为 `target != null && target.IsFlexing()`；保留原版引用清理、弹开、自毁及正常目标判断。

UMM 启用、`EnableAllFixes` 和 `EnableFaceHuggerDetachFix` 同时开启才生效，开关立即协调补丁，卸载只移除此独立 ID。没有 CMM 或网络依赖，没有吞异常的 catch 补丁，没有增加客户端攻击门禁。最初加到 CMM 的候选已撤出且未部署，最终 CMM 构建 `e19aab8d83dcd6ca0e8732577c8fdfb16cbe360657aff1a8494563a3b626a648` 不包含本修复。Utility Mod 未修改。

## 验证

.NET Framework 3.5 编译通过，DLL 13,824 字节，已部署双端并重启加载；SHA-256 为 `19A33C23850CF5242B415532867DFF0A5F9572627C62CE8A95CD9A68F6AD051F`，版本仍为 `0.3.0` 的本地更新，没有发布或推送。

离线模式（`Connect.IsOffline=True`、CMM world epoch=0）实例化游戏自带 ZSnake，构造 `dieAfterInsemination=False`、目标为空：

- 补丁开启：`detach=OK`。
- 暂时卸载本独立补丁：同一状态 `detach=NullReferenceException`。
- 恢复补丁：`detach=OK`；构造敌兵保留蛇引用时，原版清理方法返回 `victimLinkCleared=True launched=True`。

FRP 双端进入同一 Workshop，分别在房主与加入方构造两种状态并调用敌兵的原版脱离入口：

| 执行端 | 蛇目标 | 结果 |
| --- | --- | --- |
| 房主 | 空 | detach=OK、敌兵/蛇引用均清空、launched=True |
| 房主 | 正常敌兵 | detach=OK、敌兵/蛇引用均清空、launched=True |
| 加入方 | 空 | detach=OK、敌兵/蛇引用均清空、launched=True |
| 加入方 | 正常敌兵 | detach=OK、敌兵/蛇引用均清空、launched=True |

加入方 Harmony 查询确认此处 Transpiler 归属仅为 `GJKen.BroforceBugFix.FaceHuggerDetach`。这些是各端分别执行的受控局部状态测试，不是测试对象网络生成同步的验收，也不是自然 AI 离线重现整个喷血现场。没有用此结果声称最初引用丢失已修复；其触发原因仍待后续自然现场定位。正常目标的自毁/英雄 Flex 分支及长期战斗未扩测。

测试克隆已逐个销毁，临时脚本和截图清理，双端测试游戏关闭。保留的结论是：原版空目标异常得到独立修复，联机最初触发因素仍未定性。
