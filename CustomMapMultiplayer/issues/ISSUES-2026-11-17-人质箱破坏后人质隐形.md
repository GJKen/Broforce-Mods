# 人质箱破坏后人质隐形

## 现场与根因

2026-11-17，用户反馈 `Two Random Guys Save The Princess`、`Test Evan2`、关卡索引 11 中人质箱被破坏后双端分歧。两端实际加载协议 14、MVID `8aff786c-56a0-43dd-86b8-c5059f1bed77`。

- 箱体 NID `[149 0 24320 4]`，两端位置 `(544,240)`、血量 0、`destroyed=True`。
- 人质 `RescueBro` NID `[149 0 24320 8]`，两端位置 `(552,216)`、血量 1、`freed=True`、`rescueState=Idle`，均已脱离箱体并挂到 `MapController`。
- 本机人质和 `SaveMe` 气泡 Renderer 均启用；5700G 上两者 Renderer 均禁用，但对象仍活动。5700G 箱体的 `PresentedFlags=Destroyed`，预测已经结束；本机为 None。

`HideWorldHitRenderers` 在预测破箱时递归隐藏所有子 Renderer，包括尚未脱离箱体的人质与气泡。确认箱体破坏后，`FinishWorldHitPresentation` 为保留破箱效果不会恢复箱体 Renderer，导致一并隐藏的人质即使已被原版正常释放也永久隐形。此问题与此前十字架村民的未初始化坐标问题不同。

## 修复

隐藏破坏对象的图像时，按最近的 `BroforceObject` 父组件判断归属；拥有独立有效网络 ID 的子对象保留自身显示状态。箱体、栏杆仍隐藏，人质及气泡不再被连带隐藏；原本隐藏的人质武器也不会被强行显示。无需新增协议字段，保持协议 14，救援、换人和生命数流程沿用原版。

- `Test-WorldPickups.ps1` 127 项回归检查通过，新增覆盖同一 GameObject ID、不同组件 ID 的人质、气泡、原本隐藏的武器、破坏确认与预测拒绝。
- 标准 .NET Framework 3.5 编译成功，构建 `9e006c3a60921da350796d2a077d88fd0e71c16b6f17373dae29a47ace0e0159`，DLL 487,424 字节。标准脚本先终止并确认双端游戏退出，再部署 DLL 和 `Info.json`，同步更新发行包。
- 双端重启实际加载 MVID 均为 `3a6958e7-fbe2-47fe-9fc3-0d39644fbd4d`。

- 同一调用内确认预测已触发，隐藏集合只有 2 个箱体 Renderer；此时箱体血量仍为 5、`destroyed=False`，人质与气泡 Renderer 均保持启用。
- 伤害在拥有端结算并跨端确认后，两端箱体血量均为 0、`destroyed=True`。
