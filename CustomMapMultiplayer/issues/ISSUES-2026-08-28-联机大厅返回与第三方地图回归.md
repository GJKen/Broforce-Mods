# 联机大厅返回与第三方地图回归

## 状态

当前工作区的最近一轮改动出现了严重联机回归，暂不应继续编译或部署。用户最新实测确认：加入方进入房主大厅后，第三方 Workshop 地图没有按房主地图进入，而是进入官方 `Test Evan2`；此前还出现返回后主菜单 UI 消失、关闭 Mod 按钮后官方房间列表无法刷新。

## 本次改动要求

### Mod 标识与部署

- Mod 名称统一为 `CustomMapMultiplayer`。
- 旧版 Mod 标识不再出现在源码命名空间、入口配置、程序集名称、安装包目录、部署目录和日志目录中。
- 构建脚本应生成并部署新的 DLL，同时避免旧 DLL 与新 DLL 并存造成 UMM 重复加载或加载错误。

### UMM 设置面板

- 设置面板使用 `Multiplayer Options` 作为联机功能分组名称。
- 设置界面采用左侧竖向功能列表、右侧显示当前功能内容的布局。
- 语言选项放在左侧功能列表中，并位于 `Diagnostic Logs` 上方；支持跟随系统、English、中文。
- Workshop 地图、FRP Direct、AFK、诊断日志等功能的开关和设置保持原有含义，关闭功能后不得继续影响官方原生联机流程。
- Workshop 选项需要明确说明官方地图和第三方 Workshop 地图的操作方式，尤其是房主填写 Workshop ID、加入方跟随房主地图的前置条件。
- 复选框说明文字应与控件内容对齐；悬浮提示框应有不透明背景，文字居中且不能遮挡其它设置内容。
- FRP Direct 角色说明使用“在下面按钮中选择你的FRP Direct 角色”。

### 诊断日志

- 诊断日志继续写入 Mod 自己的日志目录。
- 设置中可以调用系统资源管理器打开日志目录。
- 日志和诊断功能不得改变官方大厅房间搜索、刷新、加入和退出行为。

### 联机行为

- 开启第三方地图联机时，房主和加入方必须进入同一个房主指定的 Workshop 地图，不得回落到官方 `Test Evan2`。
- 关闭所有 Mod 联机按钮后，官方地图和官方房间应完全走游戏原生流程，房间列表可以正常刷新。
- 从联机大厅、地图或结算界面返回后，主菜单的按钮、文字、选中框、Logo 和输入状态必须恢复。
- 主菜单恢复状态不能因为协程未完成、场景切换、离开房间或清理流程而永久残留。
- 原生 Steam 联机和 FRP Direct 联机的状态清理必须互不干扰。

## 已观察到的回归

1. 加入方进入第三方地图联机后实际加载官方 `Test Evan2`，房主地图身份没有正确传递或被加入流程覆盖。
2. 加入方进入联机大厅后返回，主菜单 UI 可能整体隐藏。
3. 即使关闭 Mod 设置中的按钮，官方房间列表仍无法刷新，说明相关 Harmony 补丁或运行时状态没有按开关停用。
4. 之前还发生过官方地图 `Test Evan2` 中的原生崩溃；该问题需要与本轮 UI、地图注入和大厅状态回归分开验证，不能仅凭一次崩溃归因于改名。

## 验收标准

- 双端完全退出并重启后，关闭所有 Mod 联机功能，官方房间可以刷新、加入、退出并返回正常主菜单。
- 双端开启第三方地图联机，房主配置一个有效 Workshop ID，加入方加入后双方都加载房主指定地图，而不是 `Test Evan2`。
- 在上述两种模式之间反复进出大厅，主菜单 UI 始终可见且可操作。
- UMM 只加载一份新名称程序集；日志能记录实际场景、地图身份、房间刷新/加入结果和主菜单恢复阶段。

## 回退原则

- 不直接回退整个仓库，因为 `BroforceBugFix`、`AGENTS.md` 和其它目录存在独立修改。
- 优先只回退 `CustomMapMultiplayer` 的本轮未提交代码，并保留本 issue 文件作为回归记录。
- 回退前先确认目标基线提交和工作区中哪些改动属于本轮，回退后再重新构建部署；运行中的游戏不会热加载回退后的 DLL。
