# Steam 房主身份重复查询造成联机 CPU 负载

## 状态

用户已实测 BroforceBugFix `0.5.0`，确认游戏恢复稳定高帧、没有问题。本次将有效修复精简整合到 CustomMapMultiplayer `0.5.1`；下方原始计时与验证保留为历史证据，不把它当作整合版的新一次双端实测。

整合后用户进一步实测确认“加入方联机帧率也正常了”。房主与加入方的帧率体验均已通过用户验收；用户未提供具体 FPS 数值或地图信息，不补写定量结果。

## 整合实现

- `src/HarmonyDiagnostics.SteamHost.cs` 复用现有 Harmony 实例，在 `Start()` 安装，在 `Stop()` 卸载并清空缓存。无需独立 Harmony ID、配置开关或协调逻辑。
- 保留同帧、同网络层、同房间的原版 getter 结果缓存，以及 Steam 回调泵前后、成员/数据回调前的失效处理。离线、加入方 `false` 和身份变更语义不变。
- 不迁入 0.4.0 的 Mook 裁剪实验，不调整敌人更新范围、AI 或网络协议；Steam/FRP 传输选择和 Workshop 注入设置不影响该缓存的生命周期。
- 此前实现位于 BroforceBugFix，以下版本号 `0.4.0`、`0.5.0` 均指其试验版；整合版的构建和验证另记于文末。

## 根因及源码证据

原版 `SteamLayer.IsHost` 在线时每次执行：

```csharp
SteamUser.GetSteamID() == SteamMatchmaking.GetLobbyOwner(this._lobbySteamID)
```

`NetworkObject.IsMine` 在对象所有者为 `PID.TargetServer` 时调用 `Connect.IsHost -> SteamLayer.IsHost`。敌人的移动、陷阱检测、蹲伏和镜头外检查等路径多次判断所有权，因此 Steam 身份查询成本分散在这些调用者中。只测 `SteamLayer.Update` 会漏掉这部分负载。离线时 `_lobbySteamID == CSteamID.Nil` 直接返回，不发生这些重复的 Steam API 调用；这提供了联机与本地负载差异的一条具体机制。

本轮修复前的 240 帧定位采样：`SteamLayer.get_IsHost` 约 `245.97` 次/帧，累计 `10.2483 ms/帧`。此前裁剪候选的 `RunForceExtents` 约 `0.1279 ms/帧`，不能解释主要负载。`Mook.Update` 的较高耗时包含了嵌套的身份查询，不等于纯 AI/物理开销。

本轮现场为 `Contra Predator II / Test Evan2`，Steam 在线房主、1 名本地玩家。它可验证重复查询及补丁效果，不构成用户双端约 40 FPS 现场的复现。没有调整帧率上限、垂直同步或修改 `CustomMapMultiplayer`。

## BroforceBugFix 0.5.0 的修复边界（历史）

- 新增独立补丁 `SteamHostQueryFix`，Harmony ID 为 `GJKen.BroforceBugFix.SteamHostQuery`；独立设置 `EnableSteamHostQueryFix` 默认开启。
- 同一帧、同一个 `SteamLayer` 实例和同一个 `LobbySteamId` 复用原版查询结果。每次缓存失效后的第一次读取仍运行原版 Steam 身份查询。
- 帧变化、网络层实例变化或房间 ID 变化后重新查询。`SteamAPI.RunCallbacks` 前后，以及房间成员/数据回调开始前清除缓存，使房主迁移处理不沿用旧身份。
- 离线 getter 直接走原版。在线房主和加入方都可减少重复查询，不改变身份结果、网络协议或 RPC 内容。
- 独立设置、主开关、UMM 禁用或插件卸载均移除补丁并清空缓存。没有停用额外敌人组件，也没有调整 AI、触发器、空中单位或尸体状态。
- `0.4.0` 的房主裁剪范围补丁保持原状，仍有独立开关；此前用户报告该优化不足的结论不变。

## 本轮验证

确认 Broforce 进程完全退出后构建并部署 `0.5.0`，随后启动游戏确认补丁实际加载。第一次编译因 .NET 3.5 编译器要求显式传入旧 Harmony API 参数失败；修正后构建成功，失败产物未部署。构建配置未设置 `TestDeployModPath`，因此只更新项目安装包和本机 UMM。

在同一在线房主场景内，关闭/开启新修复各采集 180 帧，阶段前各等待 30 帧。通过临时 Harmony 计时和 getter 原方法入口计数得到：

| 指标 | 关闭新修复 | 开启新修复 |
| --- | --- | --- |
| 原版 `IsHost` getter 执行次数/帧 | 248.69 | 1.01 |
| `IsHost` 累计耗时 | 10.3550 ms/帧 | 0.1079 ms/帧 |
| `Mook.Update` 累计耗时 | 7.2699 ms/帧 | 1.3184 ms/帧 |
| `DisableWhenOffCamera.Update` 累计耗时 | 2.3990 ms/帧 | 0.0970 ms/帧 |
| `Mook.Update` 次数/帧 | 14.08 | 14.08 |
| 活动 Mook 数（阶段起止） | 14 | 14 |

以上是带采样开销的托管方法累计耗时，嵌套调用不可相加，也不是实际 FPS 测试。菜单阶段启动过一次采样，进入游戏前即取消，没有纳入表格。游戏原有 TestMod 在加载地图时自动清理过 3 个可见 Mook；开关对照两阶段都在该行为完成之后进行，活动敌人数保持一致。没有以减少敌人数证明修复通过。

必要的行为检查结果：

- 连续读取缓存结果与原生 Steam 查询一致：通过。
- 未加入房间的独立 Steam 网络层对象仍返回原版离线房主结果：通过；这不是离线自定义战役完整回归。
- 同帧切换网络层实例、房间 ID 后重新查询：通过。
- 对原版 getter 临时注入可控返回值，检查加入方 `false`、房主 `true` 缓存及失效后身份变化：通过；这不是实际双端加入或房主迁移测试。
- 实际执行 Steam 回调泵后缓存清除，成员/数据回调的失效补丁已挂接：通过。
- 独立设置及主开关移除/恢复补丁，插件卸载移除补丁、清空缓存并恢复原版身份结果：通过。

验证结束后恢复设置、卸载临时采样和测试脚本并删除临时源码，关闭 Broforce 并确认进程退出。
