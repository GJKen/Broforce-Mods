# 敌方导弹爆炸缺失与地形蓝闪

2026-11-14：已定位、修复、Release 构建并部署双端；FRP 双端受控短测通过，随后补齐火箭坦克、炮坦克和炮车的原生开火复测，加入方 10 发弹体的对应爆炸均正常执行。用户随后确认加入方实际开火破坏地形时蓝闪已消失，该项已通过用户实测，不再安排复查。完整车辆 AI 战斗和长时间游玩仍待观察。Utility Mod 只作对象清单参考，未修改。

## 根因与源码依据

### 爆炸消息晚于弹体移除

`HarmonyDiagnostics.WorldProjectiles.cs` 原先以 `immediate=false` 发送爆炸表现 RPC，以 `immediate=true` 发送移除快照。原版 `RPCController.cs`、`Networking/Networking.cs` 会把前者放入延迟队列；加入方先移除弹体，再处理爆炸消息时已找不到对象，因此直接丢失表现。当前地图的 `MookBazooka` / `RocketSeeking` 已现场复现；临时只调整消息立即执行属性后，同一弹体恢复爆炸。

正式修复把爆炸表现和本地弹体生成描述都改为立即执行，与同一可靠流上的移除保持执行顺序。生成描述也需同步调整，避免 `SpawnProjectileLocally` 路径的弹体在生成前就收到爆炸或移除。协议载荷未变，仍为协议 12。

### 重型炮弹被当作普通子弹播放

接收端原先只区分 `Rocket` 和普通 `Projectile`，`HeavyShell` 因此调用了普通子弹表现。原版 `HeavyShell.MakeEffects` 包含准星消退、摇树和 `CreateHugeExplosion`，不能用基类表现代替。

修复为 HeavyShell 单独反向补丁回放原生表现，并扩展原有视觉随机状态捕获。回放仍沿用 `_worldApplying` / `WorldEffectPrefix`，抑制重复地形、单位和装饰伤害。

### 地形预测期间缺少破损背景

原版 `Block.SetCollapsedVisuals` 隐藏地形后会调用 `ShowBrokenBackground()`；`DirtBlock.ShowBrokenBackground` 创建或复用 `backgroundMesh`。加入方命中预测原先只隐藏全部 renderer，等房主确认才创建背景，期间露出蓝色远景。

修复前实际射击样本（地形 `1616,224`）：

```text
1518.991 HideWorldHitRenderers health=5 destroyed=False visible=0 background=null
1519.190 FinishWorldHitPresentation health=0 destroyed=True visible=1 background=DestroyedDirt_TOP003(Clone)/True/True
```

空窗约 199 毫秒。修复在预测隐藏时保留已有背景，没有背景则立即调用原版创建；未确认销毁时清理本次创建的背景。仅调整表现，不调整伤害、碰撞或地形结算。

关键原版源码均位于 `Broforce_src/Broforce-Source/`：`ProjectileController.cs`、`Rocket.cs`、`HeavyShell.cs`、`MookBazooka.cs`、`TankCannon.cs`、`TankrocketBattery.cs`、`TankMookLauncher.cs`、`MookArtilleryTruck.cs`、`RPCController.cs`、`Networking/Networking.cs`、`Block.cs`、`DirtBlock.cs`。

## Utility Mod Vehicles 对照

对照 Utility Mod 的 `Display/ContextMenuBuilder.cs`、`Main.SpawnUnit`，以及 `RocketLibMultiplayer/RocketLib/Utils/UnitTypes.cs` 中清单，并检查运行时实际 prefab 字段和原版发射方法。

| Vehicles 项 | 实际弹体或行为 | 本问题关系 |
| --- | --- | --- |
| CannonTank | `Shell Heavy Metal` / `HeavyShell`，另有大手雷 | 重型炮弹表现分支缺失，且受消息顺序影响 |
| RocketTank | `Rocket Tank Battery` / `RocketSeeking` | 受爆炸与移除消息顺序影响 |
| ArtilleryTruck | `Shell Heavy` / `HeavyShell`，`SpawnProjectileLocally` | 重型炮弹表现及本地生成描述顺序均需修复 |
| MookLauncherTank | `FireWeapon` 实际发射 Mook | prefab 虽有 RocketSeeking 字段，不能据此算作实际发射导弹 |
| Blimp、Turret | `BulletMook` / 普通 Projectile | 使用普通子弹表现，不属于缺失重型爆炸的对象 |
| DrillCarrier、MookTruck、Motorbike、MotorbikeNuclear、DumpTruck | 未发现 Projectile/Grenade 字段 | 清单检查未显示其有本问题所述的导弹 |

当前地图原生火箭兵另使用 `Rocket Mook Bazooka` / `RocketSeeking`。Utility Mod 的本地 Instantiate 不会自动完成跨端生成，因此没有把单端菜单生成的对象作为双端验收依据，也没有修改其生成系统。

## 逐车实际开火复测

用户随后明确确认：加入方实际开火破坏地形时，一闪而过的蓝色已消失。本项不再重复测试。

用户要求补测三种车辆自身开火后，沿用双端已进入的 FRP 房间，地图仍为 `Contra Predator II` / `Test Evan2`。双方本次启动日志确认加载的仍是上述 `a8fb9392...` 构建。本轮没有修改产品代码、Utility Mod，也没有重新构建或部署。

地图没有这三种车辆实例，因此临时在双方分别实例化原版车辆 prefab，再用 `Registry.RegisterGameObject` 登记相同的场景 NID，并把拥有者设为房主。验证两端车体及武器组件 NID 一致、房主 `IsMine=True`、加入方 `IsMine=False` 后开始测试。这是测试脚本显式成对登记，不代表 Utility Mod 已支持联机生成，也不作为产品自动生成同步的验收。

通过原版 `PolymorphicAI` 的 Fire 动作队列触发正常更新流程：坦克经过 `Tank.RunAI`、`TankWeapon.RunFiring` 后调用实际炮塔 `FireWeapon`；炮车经过 `MookTruck.RunAI` 的原生开火 RPC，随后由 `MookArtilleryTruck.AnimateIdle` 完成展开和三连发。没有直接调用 ProjectileController 代替车辆发射，也没有缩短弹体寿命或手动调用爆炸。测试车辆临时增加血量，开火时给车辆及存活英雄加临时无敌，以免场内伤害打断样本；弹体仍使用原始武器参数和碰撞逻辑。

| 车辆 | 车体 NID（SID / Owner / GameObject / Component） | 有效弹体编号 | 加入方结果 |
| --- | --- | --- | --- |
| RocketTank / TankrocketBattery | `91 / 0 / 60112 / 3`，炮塔组件 17 | `60113`、`60114`、`60115`、`60116` | 4/4：CreateExplosionRangePop + CreateShaderExplosion |
| CannonTank / TankCannon | `91 / 0 / 60144 / 3`，炮塔组件 17 | `60162`、`60163`、`60164` | 3/3：CreateHugeExplosion |
| ArtilleryTruck / MookArtilleryTruck | `91 / 0 / 60165 / 4` | `60166`、`60167`、`60168` | 3/3：CreateHugeExplosion |

以上弹体均为 `SID=91 / Owner=6 / Component=2`，逐个编号对照房主生成与加入方接收记录，10/10 都满足 `RECEIVE` → 对应 `EffectsController` 爆炸调用 → `REMOVE`，没有先移除后丢失表现。

- 火箭坦克原生四孔齐射，`Rocket Tank Battery` / `RocketSeeking` 初始寿命 3 秒，加入方四枚均恢复范围环及 ShaderExplosion。
- 炮坦克从正常地图内站位 `(640,232)` 发射 `Shell Heavy Metal` / `HeavyShell`，初始寿命 6 秒。房主实际碰撞爆炸时分别剩余约 `4.90 / 4.80 / 4.72` 秒，命中位置分别为 `(318,170)`、`(300,74)`、`(284,40)`；加入方对应三次原生大爆炸均先于移除。
- 炮车实际展开后通过 `SpawnProjectileLocally` 连发三枚 `Shell Heavy` / `HeavyShell`，初始寿命 6 秒，实际碰撞爆炸时剩余约 `5.87 / 5.32 / 4.82` 秒。加入方在帧 `41050 / 41104 / 41155` 分别接收到上述三枚弹体并播放大爆炸。

首次测试车在布置后被场内伤害击毁，以及炮坦克落入前次爆炸造成的坑洞、在界外发射的样本，均排除在上表有效结果外；炮坦克更换完整地面后重新验证。通过范围是三种车辆的实际开火及加入方爆炸表现，不扩展为完整自然索敌、行驶、全战斗或长期联机验收。

复测后两端显式销毁测试车辆，关闭双方游戏，并用本机进程查询和远端 tasklist 确认退出；临时脚本已删除。双方最新 `.log`、`.trace.log` 已读取，未发现本轮弹体表现相关异常；入图时 `CheckPoint.Update_Patch1` 空引用仍按前述独立边界保留。
