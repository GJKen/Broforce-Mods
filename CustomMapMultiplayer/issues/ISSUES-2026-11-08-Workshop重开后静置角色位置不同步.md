# Workshop 重开后静置角色位置不同步

## 现象与范围

Steam Lobby、Workshop `3715087178`、`Bromandy_Ptr1 / Test Evan2`，内网房主与本机加入方。重开关卡后加入方不按键时，两端观察到的加入方 X/Y 不一致；方向输入后收敛。精简前的构建和阶段二、阶段三均已复现，不能归因于第三阶段精简。

用户在第三阶段补测后明确要求修复。本次修改出生同步及同轮发现的测试脚本错误；旧精简验收记录保留当时的真实结果。

## 根因与修复

原生 `BroBase.Start` 对本地角色执行 `SetSyncingInternal(false)`，`BroBase.Update` 要等到方向输入才开启同步。Workshop 出生后的物理过程已经改变了本地角色位置，但静置时后续位置不再发送。旧 DLL 的双端探针记录加入方本地 `(482.000, 201.158)`、`Syncronize=false`，房主镜像 `(199.836, 104.000)`；不发送方向输入，仅调用原生 `EnableSyncing(true, true)` 后，两端均为 `(482.000, 201.158)`。

在现有 `TryRebroadcastWorkshopSpawns` 的出生点 RPC 后开启原生同步。沿用既有 750ms 延迟，不新增定时扫描、重试或补丁入口；只有配置中的 Workshop 联机场景、本地拥有且 `IsAliveAndSpawnedHero()`、尚未同步的角色会执行。死亡、未完成出生的角色不进入；出生点计算和原有重广播顺序保留。

## 建房 AddPlayer 异常

临时 Harmony finalizer 只观察异常并原样返回。旧快速建房脚本在 `newJoin` 调用 `HeroController.AddLocalPlayer`，实测 `pidMine=true`、`HeroController.Instance=null`，原生 `AddPlayer` 因而空引用。该界面原本使用 `JoinScreen.RequestJoin` 登记槽位，HeroController 直到关卡内才存在。单纯等待 HeroController 的尝试停留在准备界面，已撤销。

修正 Unity Inspector 的 `scripts/csharp/quick-online-workshop.cs`：等待 JoinScreen，按原生流程递增加入请求并向服务器发送 `JoinScreen.RequestJoin`，保留原生姓名选择、控制器、倒计时和重试间隔。最终从准备界面进入目标地图，异常观察器为空。没有修改 Mod 来吞掉 AddPlayer 异常。该异常属于测试脚本使用错误接口，与关卡内静置同步关闭是两条独立路径。

## 构建和双端回归

标准构建成功，最终运行构建为 `59f0931c93cb7b82419c19bb8fc7f1a4e3973b230097a2c1ff03e590d2dc47b4`。退出双端旧进程后部署 DLL 与 Info.json，重新启动后分别读取运行构建，版本一致。

| 路径 | 实际结果 |
| --- | --- |
| 晚加入后静置 | 双端 2 人存活，各有唯一本地角色，X/Y 一致，原生同步已开启 |
| 第一次重开、不输入 | 加入方两端均为 `(482.000, 200.108)`、同步开启；房主两端均为 `(144.126, 104.000)` |
| 第二次重开、不输入 | 加入方两端均为 `(482.000, 213.447)`、同步开启；房主两端均为 `(148.100, 104.000)` |
| 双方方向输入 | 两名角色均实际移动，停止后双方观察到各自一致的 X/Y |
| 加入方、房主分别存活 AFK 返回 | 双端人数各按 2→1→2 变化，返回存活、同步开启、加入请求缓存为 0 |
| 加入方原生死亡后 AFK 返回 | 双端保持死亡、0 生命、无角色，槽位仍参与，缓存为 0，没有错误复活 |

死亡测试读取 Utility 无限生命原值为 false，测试后恢复同一值，没有保存配置覆盖。测试使用现有自动清敌，沿用原有角色选择与地图配置；正常加载可能更新最近地图记录。

当前结论只覆盖本地图的上述双端路径；FRP、多加入方、其它地图、通关、救援、主机迁移和长期高延迟未在本轮重新验证。
