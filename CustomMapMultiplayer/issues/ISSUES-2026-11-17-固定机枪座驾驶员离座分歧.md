# 固定机枪座驾驶员离座分歧

## 现场与根因

用户在 2026-11-16 反馈：攻击把机枪座前的敌人击退，敌人回到机枪座附近后，双端显示出现分歧。现场位于 `Two Random Guys Save The Princess` 的 `Test Evan2`，关卡索引 11。

只读检查发现，两端独立士兵的网络 ID、位置和血量一致，`pilottedUnit` 均为空。机枪座同为 7 血、位置 `(400,152)`，但本机 `mookKilled=True / driverSprite.activeSelf=False / CanFire=False`，5700G 为 `False / True / True`。两端 CMM 加载 MVID 均为 `973098cf-07ea-43a1-bff4-10f69826658e`，排除双端构建不同。

原版 `MookGunplacement.Damage` 将 `mookKilled` 设为 true，通过 `SpawnMook` 隐藏内置驾驶员并网络生成独立士兵。CMM 仅在对象拥有端结算伤害，快照没有包含这个私有字段，因此副本保留了驾驶员图像和开火资格；独立士兵走回附近时看起来像重新上座。

## 修复

- 世界快照新增 `GunnerEjected`，从原版 `mookKilled` 采集，并纳入可靠关键状态变更判断及二进制读写；协议升级为 14。
- 副本应用时设置 `mookKilled` 和驾驶员图像可见性，保留原版 `CanFire` 判断。
- 在死亡重放前恢复离座字段，不调用 `SpawnMook`，避免重复生成已由原生网络创建的士兵。

## 验证与部署

2026-11-17，`Test-WorldPickups.ps1` 的 123 项检查通过，包括新增的离座状态采集、可靠变更、连续快照编解码、重复接收、占座基线恢复检查；`git diff --check` 通过。标准 `BuildAndDeploy.ps1 -Configuration Release` 使用 .NET Framework 3.5 编译成功，先终止并确认双端游戏退出，再部署 DLL 和 `Info.json`，同步更新项目发行包。

- 构建：`72179e14f549d1e2fe8e65b2e15e58e9e08897dbb68051cc83cfcf870ea1709b`。
- DLL：487,424 字节；双端重启实际加载 MVID `8aff786c-56a0-43dd-86b8-c5059f1bed77`，协议均为 14。
- 通过 Steam Lobby 将双端带回同一地图、同一关卡，初始机枪座两端都是 25 血、驾驶员可见、`CanFire=True`。
- 在拥有端对原版机枪座执行一次受控 `Damage(1, DamageType.Melee, ...)`，血量 25→24。两端随后都是 `mookKilled=True / driverSprite.activeSelf=False / CanFire=False`，位置仍为 `(400,152)`。
- 弹出士兵网络 ID 两端同为 `[53 6 60315 3]`，血量均为 3；士兵返回 `(403.6794,152)` 附近后，机枪座仍为空座且不可开火，没有副本额外生成的驾驶员。
