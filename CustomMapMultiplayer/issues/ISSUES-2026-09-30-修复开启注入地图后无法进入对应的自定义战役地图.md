## 对话总结

### 1. 初始排查方向被重新限定

会话开始时曾从 Steam Lobby、离线状态和没有有效 Lobby ID 的方向排查三方图联机失败。之后用户明确指出，当前要解决的问题是：

> 选择了注入地图的功能，然后无法进入对应的本地自定义战役地图。

从这一点开始，定位重点改为：Workshop 地图注入逻辑是否错误接管了原生自定义战役入口，或者清理了原生自定义战役所需的运行态字段。

### 2. 第一轮修复：避免注入覆盖原生自定义战役

代码检查发现，插件在 `WorldMapController.EnterMission`、`GameState.LoadLevel` 及场景生命周期中会维护 Workshop 注入状态。原生自定义战役也会经过 `newJoin` 和 `GameState.LoadLevel`，因此可能被插件误认为是在线 Workshop 注入会话。

第一轮修改包括：

- `ApplyWorkshopState` 在已有原生 `loadCustomCampaign` 状态时跳过线上 Workshop 注入。
- `GameState.LoadLevel` 的重复场景加载抑制只在在线 Workshop 会话中执行。
- 非在线流程清理残留的重复加载抑制状态，避免阻塞本地地图加载。

该版本能够成功构建并部署，但用户复测后仍可复现问题，说明“仅防止注入覆盖字段”不足以解决整个进入流程。

### 3. MCP 快速复现步骤

本次复测没有依赖截图或手动点击菜单，而是通过 Unity Inspector MCP 的 `execute_code` 直接调用游戏内对象和私有方法。步骤如下。

1. 从主菜单进入自定义战役菜单：

```csharp
MainMenu.instance.TransitionToCustomCampaign()
```

2. 等待 `NewCustomCampaignMenu` 加载后切换到已订阅列表，并调用私有 `SetTab`：

```csharp
SingletonMono<NewCustomCampaignMenu>.Instance.highlightedTabIndex = 3

typeof(NewCustomCampaignMenu)
    .GetMethod(
        "SetTab",
        BindingFlags.Instance | BindingFlags.NonPublic)
    .Invoke(
        SingletonMono<NewCustomCampaignMenu>.Instance,
        null)
```

3. 等待订阅列表加载完成后，直接调用私有 `LaunchWorkShopLevel`，等价于选择并启动目标 Workshop 自定义战役：

```csharp
typeof(NewCustomCampaignMenu)
    .GetMethod(
        "LaunchWorkShopLevel",
        BindingFlags.Instance | BindingFlags.NonPublic)
    .Invoke(
        SingletonMono<NewCustomCampaignMenu>.Instance,
        new object[]
        {
            SingletonMono<NewCustomCampaignMenu>.Instance
                .entries[7]
                .workshopDetails
        })
```

本次固定复测目标为 `entries[7]`：

- 地图：`The Eagles Cry`
- Workshop ID：`3715087178`
- 本地文件名：`Bromandy_Ptr1.bfg`

每次调用后需要采样以下状态，确认流程是否只进入 `newJoin`，还是继续加载实际战役地图：

```text
SceneManager.GetActiveScene().name
LevelSelectionController.loadCustomCampaign
LevelSelectionController.isOnlineCampaign
LevelSelectionController.currentWorkshopLevel
LevelSelectionController.currentCampaign
LevelSelectionController.campaignToLoad
GameState.Instance.customLevelID
GameState.Instance.sceneToLoad
```

源码分析确认的原生流程如下：

```text
NewCustomCampaignMenu.LaunchOfflineCampaign / LaunchWorkShopLevel
  -> 设置 campaignToLoad
  -> 设置 loadCustomCampaign = true
  -> 设置 currentCampaign
  -> 设置 sceneToLoad = newJoin
  -> 加载 newJoin
  -> JoinScreen.StartGame
  -> LevelSelectionController.GotoNextCampaignScene
  -> GameState.LoadLevel
  -> 加载实际战役地图
```

同时确认，`SteamLayer.LeaveMatch` 会在 `newJoin` 场景切换期间触发。旧清理逻辑把这次原生自定义战役切换误判为旧的 Workshop 注入会话，并清空了：

- `currentCampaign`
- `loadCustomCampaign`
- `currentWorkshopLevel`
- `customLevelID`

清理后，后续加载流程失去自定义战役上下文，最终可能进入 `LoadingScreen`，再因加载失败返回 `MainMenu`。

### 4. 最新修复：保留原生自定义战役状态

最新修改在 `HarmonyDiagnostics.Lifecycle.cs` 增加了原生自定义战役判断，并在 `HasInjectedWorkshopRuntimeState` 中优先排除这类状态：

```csharp
private static bool HasNativeCustomCampaignSelection()
{
    return Connect.IsOffline &&
        LevelSelectionController.loadCustomCampaign &&
        LevelSelectionController.currentCampaign != null &&
        (LevelSelectionController.currentWorkshopLevel != null ||
         !string.IsNullOrEmpty(LevelSelectionController.campaignToLoad));
}
```

这样，原生自定义战役触发 `SteamLayer.LeaveMatch` 时不会再被当作插件残留注入状态清理；真正的在线 Workshop 注入会话仍可走原有清理逻辑。

相关文件：

- `src/HarmonyDiagnostics.Lifecycle.cs`
- `src/HarmonyDiagnostics.Patches.cs`
- `Release/UMM/Mods/CustomMapMultiplayer/CustomMapMultiplayer.dll`
- `Release/CustomMapMultiplayer.zip`

## 当前问题边界

当前不能再简单归因于 `SteamLayer.LeaveMatch` 清空字段，因为最新修复已经保留了这些字段，但用户仍无法正常进入地图。需要进一步区分以下情况：

1. `newJoin` 中的开始按钮或菜单状态没有正常完成初始化。
2. `JoinScreen.StartGame` 没有触发，或触发后没有调用 `GotoNextCampaignScene`。
3. `GameState.LoadLevel` 收到的 `sceneToLoad`、`currentCampaign` 或关卡索引不符合原生要求。
4. Workshop 自定义战役同时出现 `Connect.IsOffline=True` 和 `isOnlineCampaign=True`，导致原生流程选择了错误分支。
5. 实际地图加载失败，但当前诊断日志没有记录到 `LoadingScreen` 的错误原因。

旧日志曾出现：

```text
NullReferenceException
NewCustomCampaignMenu.RunTheHighlight()
NewCustomCampaignMenu.Update()
```

但该异常来自旧构建，且不是当前最新复现的直接证据，不能单独作为当前根因。
