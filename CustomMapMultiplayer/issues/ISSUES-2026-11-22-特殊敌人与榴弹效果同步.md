# 特殊敌人与继承榴弹效果同步

修复引入于0.5.2—0.5.4，当前0.5.6继续保留，世界协议25。范围为Workshop世界中的指定原版敌人链路，不是全局召唤或音画事件系统。

## 游戏内表现与修复

| 对象 | 原问题表现 | 当前处理 |
| --- | --- | --- |
| Warlock | 一端看见投射器，另一端缺少后续传送门、召唤单位或抛出 | 同步Setup所需身份与目标配置，由拥有端选择原生召唤预制体；镜像按同一身份重建门/子物并消费原生抛出，避免镜像自行随机生成 |
| Lost Soul | 镜像俯冲或最终效果存在，但跨拥有端接触没有在目标拥有端结算 | 保留具体接触来源，向目标拥有端转交合法接触伤害；最终效果与接触分别处理，不重复结算 |
| Screecher | 镜像可点燃或移动，但缺最终酸爆及对应作用 | 补齐镜像最终效果和原生酸作用路径，拥有端仍负责有效结算 |
| Baneling | 镜像俯冲后缺最终酸爆或跨端酸作用 | 补齐最终效果及来源关联，不以此改写原生俯冲方向 |
| Mega等继承榴弹 | 两端有同一枚榴弹，但镜像端缺爆炸产物 | 使用Module与MetadataToken比较实际继承效果方法定义，确保正确安装MakeEffects回放钩子 |

## 验证结果

- Warlock真实配置消息被完整消费，门、召唤单位及抛出使用对应网络身份；拥有端随机选择不由镜像再次生成。
- Lost Soul取得自然跨端接触代表：同一来源Melee4在目标拥有端执行一次，健康值5000→4996；最终Melee0单独结算且没有额外降血，镜像接触被抑制。
- Screecher/Baneling取得同源酸作用覆盖及双端最终产物。Acid0表示命中了原生酸作用分支，不证明Acid9或额外扣血。Baneling历史方向差异没有声明修复。
- Mega明确受控进入榴弹阶段，由原生武器生成和发射。六枚同NID榴弹逐枚一次发送、有效接收及实际Large/Small/Glow产物一致，随后原生移除；镜像没有反向重复发送。
- 后续精简构建复验了代表性坦克与受控Mega实际效果，并比较未变化的方法和真实补丁目标；最终0.5.6的局部字段读取另做双端差分。没有把历史修复样本称作每次版本都全部重跑。

## 验收边界

Mega阶段、武器开关及部分镜头位置属于受控准备，自然阶段入口仍未验收。客户端部分伤害样本只有精确launcher/Boss来源，不能冒认单枚榴弹身份归因。所有朝向、晚加入、混装、任意地图和长期联机不在完整覆盖声明内。

临时对象、测试补丁和脚本已清理，原设置恢复，双端游戏真实进程均已确认退出。原始逐批交接、运行输出、截图及测试基线仅本地保留；此公开问题记录不依赖这些文件。

当前发行产物与优化说明见 [0.5.6版本说明](../docs/RELEASE-0.5.6.md)，其它历史修复见 [问题索引](README.md)。
