## 阅读规则

1. 判断双方 DLL 是否一致时，优先比较运行日志中的 `BUILD_INFO buildHash`，不要只比较文件名、大小或修改时间。
2. “编译成功”不等于“联机测试通过”；只有明确记录实际测试结果的轮次才能作为验收依据。
3. 涉及网络根因时，应收集本次实际参与测试的所有端日志。异地端只能提供日志时，需要明确没有 MCP、UMM 日志或 `error.log` 的证据边界。
4. issue 中标明“改动恢复”“已撤销”或“未定位”的内容不得复制回当前实现，除非重新验证。
