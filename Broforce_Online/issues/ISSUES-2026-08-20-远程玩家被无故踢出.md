## 根因分析

### 主要 Bug：房主无故 Dropout 远程玩家

**触发条件：** 远程玩家通过 late join 加入后，经历切换关卡，在第二次场景通过 `RequestJoinGame` 重新加入，然后被房主 dropout。

**当前日志无法判断 Dropout 的触发原因**——Mod 的 `Dropout` 调用处没有记录调用栈或触发上下文。已在本轮修复中增加了调用栈日志（见修复部分）。

### 次要 Bug：Dropout 后远程侧连带踢了房主角色

远程侧在收到 `DropoutRPC(playerNum=1)` 后，不仅 dropout 了自己，还错误地 `Dropout(playerNum=0)`（房主角色），导致全部槽位清空。

### 次要 Bug：重加入机制在全部槽位清空后失效

`AddLocalPlayer(playernum=-1, ...)` 持续返回 -1，可能是因为游戏原生状态在全部 dropout 后拒绝分配新槽位。

### 反编译源码核心方法

**SpawnJoinedPlayers()**（HeroController.cs:221-244）
```csharp
for (int i = 0; i < players.Length; i++)
{
    if (playersPlaying[i] && players[i] == null && PIDS[i].IsMine)
    {
        Networking.RPC(PID.TargetAll, AddPlayer, i, playerControllerIDs[i], PIDS[i], true);
    }
}
```
**只广播 `PIDS[i].IsMine` 的槽位**，不补远程槽。远程槽的 Player 对象只能由远程客户端自己发起。

**AddPlayer(int, int, PID)**（行 3065-3080）：`IsMine` 时实例化 Player 预制体并写入 `players[]`，否则只重置网络状态。

**AddLocalPlayer(int, int)**（行 2687-2715）：房主本地角色的唯一入口，→ `RPC TargetServer RequestJoinGame`。

**RequestJoinGame(int, PID, string)**（行 2968-2992）：仅服务端执行，分配槽位 + 写 `PIDS[]/playerControllerIDs[]/SetIsPlaying(true)`。

**AutoJoinLocalHost()**（行 2718-2723）：仅在 `NumberOfPlayers()==0` 时触发。

**三个数组在 SpawnJoinedPlayers 中的角色：**
| 数组 | 作用 | 在 SpawnJoinedPlayers 中 |
|------|------|--------------------------|
| `playersPlaying[]` | 槽位是否"有人玩"的意图标记 | 过滤器①：true 才处理 |
| `players[]` | 实际 Player 对象引用 | 过滤器②：null 才发起 AddPlayer |
| `PIDS[]` | 槽位所属机器的网络身份 | 过滤器③：IsMine 才广播 |

### 旧 Bug 1：房主进不去 Workshop 地图

**根因：** 原生流程中房主本地角色必须走 `AddLocalPlayer → RequestJoinGame` 链路，但三条触发路径全被绕过：
1. `MonitorPlayerDropin` 要求玩家按键 → 房主没按
2. `AutoJoinLocalHost` 要求 `NumberOfPlayers()==0` → Mod 网络会话下不为 0
3. `HeroSelectController` 大厅选择器路径 → Workshop 注入绕过了

结果：`SpawnJoinedPlayers` 虽对房主本地槽位发起 AddPlayer 广播，但 Player 对象被服务端校验拦截/丢弃，未写入 `players[]`。房主角色只能靠晚加入机制在加入方掉线后补出来。

**修复：** `SpawnJoinedPlayersPostfix` 中房主无本地槽位时反射调用 `AutoJoinLocalHost()`。

### 旧 Bug 2：重载场景漏远程槽

**根因：** `SpawnJoinedPlayers` 只补 `PIDS[i].IsMine` 的槽位。重载时远程客户端时序未对齐，远程槽位的 `playersPlaying[i]` 已置位但 `players[i]==null`，且 `PIDS[i].IsMine==false`，SpawnJoinedPlayers 不会为它发 AddPlayer → 漏掉远程槽。

**修复：** `SpawnJoinedPlayersPostfix` 中 host 对所有 `playing && players==null` 的远程槽位广播 `AddPlayer` RPC。

### 先前 PrepareWorkshopSpawnJoinedPlayers 的不足

只清理重复本地槽位的 `playersPlaying/PIDS/controllerIDs`，**没有清理 `players[]` 引用**。若跳过的本地槽位 `players[index]!=null`，旧 Player 对象残留导致永不被重建。
