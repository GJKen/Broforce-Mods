## 修复清单

### 1. 出生点变为 AddBroToTransport（传送位置）

**触发场景：** 使用跳关机关后场景重载，`WorkOutSpawnPosition` 调用 `WorkOutSpawnScenario` 返回 `AddBroToTransport`（因为 `HeroController.BrosReleased=true` 或 `Map.GetSpawnPointPosition().x < -16f`），角色被放到传送起点 (-59,395) 而非关卡出生点 (64,80)。

**修复历程（3 次迭代）：**

| 尝试 | 修改位置 | 方案 | 失败原因 |
|------|---------|------|---------|
| ❌ 第1次 | `CaptureDeferredSpawnPosition` | 检测到 `AddBroToTransport` 时拒绝覆盖缓存 | `WorkOutSpawnPosition` 先发出 RPC 再调用 `SetSpawnPositon`，拦截时远端已收到错误位置 |
| ❌ 第2次 | `WorkOutSpawnScenario` postfix | 在原始方法返回后改 `__result` | `WorkOutSpawnPosition` 调用 `WorkOutSpawnScenario()` 后立即把返回值存入局部变量 `spawnType`，postfix 修改 `__result` 时 `spawnType` 已持有旧值 |
| ✅ 第3次 | `WorkOutSpawnScenario` **prefix** | 返回 `false` 跳过原始方法，直接设 `__result` | 在 `WorkOutSpawnPosition` 读取返回值之前就已拦截 |

**最终实现逻辑（`WorkOutSpawnScenarioPrefix`）：**
```
条件：IsWorkshopOnlineSession() && firstDeployment && !BrosReleased
  ├─ Map.GetSpawnPoint(playerNum) != null
  │   → __result = CustomSpawnPoint, position = spawnPoint.transform.position
  │   → 日志: "Redirected AddBroToTransport to CustomSpawnPoint"
  └─ Map.GetSpawnPoint(playerNum) == null
      ├─ 缓存有 CustomSpawnPoint 记录
      │   → __result = CustomSpawnPoint, position = 缓存位置
      │   → 日志: "used cached CustomSpawnPoint after Map.GetSpawnPoint returned null"
      └─ 缓存也没有
          → __result = DropInDuringGame（走 GetFirstPlayerPosition）
          → 日志: "redirected to DropInDuringGame"
```

**文件：** `HarmonyDiagnostics.WorkshopSpawn.cs`
**双端测试：** 后续日志中 `AddBroToTransport` 不再出现在 `SetSpawnPositon` 参数中 ✅
**日志观察点：** 搜索 `WorkOutSpawnScenarioPrefix`、`Redirected AddBroToTransport`、`used cached`

### 3. SwitchLevel 后 Map.GetSpawnPoint 返回 null

**触发场景：** 从第 2 次 SwitchLevel 开始，`Map.GetSpawnPoint` 持续返回 null。`WorkOutSpawnScenarioPrefix` 只能走缓存分支（日志出现 `WARN: used cached CustomSpawnPoint`）。

**根因：** `Map.spawnPoints` 在场景重载后未正确初始化——`Map.Awake()` 创建新列表，但 `SpawnPoint.Awake()` 注册到列表的时序晚于 `WorkOutSpawnScenario` 的调用。

**修复：** `WorkOutSpawnScenarioPrefix` 的 null 分支使用 `LocalWorkshopSpawnPositions` 缓存（首次部署时存入的 `CustomSpawnPoint` 位置）。

**文件：** `HarmonyDiagnostics.WorkshopSpawn.cs`
**双端测试：** 日志确认缓存回退分支被触发 ✅（出现 `WARN: used cached CustomSpawnPoint`），但每次切关都触发说明 `Map.spawnPoints` 初始化时序问题本身未根治，只是用缓存兜住了。

### 4. 广播中远程位置覆盖本地位置

**触发场景：** 日志中 `Rebroadcast: positions=0=(221.158,72,-0.02)`——player=0（本地玩家）的位置显示为 221.158,72，该值恰好等于 player=1（远程玩家）被 snap 到 221.158,72 的位置。本地玩家坐标被远程位置覆盖。

**根因：** `TryRebroadcastWorkshopSpawns` 中 `player.character.transform.position` 指向了已被 snap 的远程角色实例。`SnapFirstRemoteWorkshopCharacter` 只把远程角色 snap 到指定位置，但 `player.character` 的引用可能被共享。

**修复：** `TryRebroadcastWorkshopSpawns` 广播前扫描 `SnappedRemoteWorkshopCharacters` 字典，若 `player.character` 指向被 snap 过的远程角色则跳过该槽位。

**日志输出：** `"Skipping spawn rebroadcast for player=X: character is a snapped remote character (snapped under playerNum=Y)."`

**文件：** `HarmonyDiagnostics.WorkshopSpawn.cs`
**双端测试：** 未触发（后续日志未出现 `Skipping spawn rebroadcast`，说明该场景未复现）

### 5. SwitchLevel 后 workshop 状态丢失

**触发场景：** SwitchLevel 后 `loadCustomCampaign`、`customLevelID` 丢失，导致：
1. `Map.GetSpawnPoint` 返回 null（不再指向 Workshop 地图）
2. `BroBase.Start()` 抛 NullReferenceException（角色初始化失败）
3. `levelFinished` 卡为 true（关卡一加载就认为已完成）
4. 触发自动重载循环

**根因：** `_injectedForSession = true` 导致 `ApplyWorkshopState` 在 SwitchLevel 时完全跳过，workshop 状态不被重新注入。`GameState.LoadLevel` 使用原生状态加载，不识别 Workshop 地图。

**修复：** 移除 `_injectedForSession` 对 `ApplyWorkshopState` 的完全拦截，改为区分路径：
- `requireHost=true`（SwitchLevel 路径）：允许重新注入，设置 `customLevelID`、`loadCustomCampaign=true`，但跳过 `levelNumber=0` 覆盖
- `requireHost=false`（进图/晚加入路径）：仍受 `_injectedForSession` 拦截，防重复注入

**文件：** `HarmonyDiagnostics.Lifecycle.cs`
**双端测试：** 日志确认每次切关前都出现 `"Online workshop state injected before AdminRPC<GameState>"` ✅

### 6. 移除 _injectedForSession 导致无限加载循环

**触发场景：** 修复 5 后，房主卡在加载界面，Test Evan2 持续重复加载。日志显示 85 秒内出现 14 轮完整加载循环（`LoadLevel → OnLevelLoadComplete → LoadLevel → ...`），加入方无法进入房间。

**根因链：**
```
修复5 移除了 _injectedForSession 检查
→ 每次 GameState.LoadLevel("Test Evan2") 都触发 ApplyWorkshopState
→ ClearCurrentCampaignForWorkshopLoad() 清空 CurrentCampaign
→ 游戏检测到 campaign 为空 → 重新下载 Workshop 内容
→ OnLevelLoadComplete 触发 → 又进入 GameState.LoadLevel
→ 循环
```

**修复：** 恢复 `_injectedForSession` 检查，但只在 `requireHost=false` 时拦截。`requireHost=true` 时仍允许注入。

**文件：** `HarmonyDiagnostics.Lifecycle.cs`
**双端测试：** 修复后登录→选择→进入流程恢复 ✅

### 7. 跳关后角色死亡（Lives=0）

**触发场景：** 跳关后房主角色 `lives=0` 死亡，无法操作。加入方退出重入后能操作（没死），但房主仍死亡。加入方重入后房主 esc 重开，地图对了但房主仍死亡。

**根因（2 层）：**
- 第 1 层：`Player.Start()` 中 `IDroppedOutThisRound == true` 时设 `Lives=0`。该标志在 `DropoutRPC` 设为 true 后从不清除，每次切关新建的 Player 都继承 `lives=0`。
- 第 2 层：`PlayerStartPostfix` 的 `lives<=0` 检查从不触发，因为 `Player.Start()` 本身已经设了 `Lives=1`，postfix 运行时看到的是 1 不是 0。死亡发生在 `Player.Start()` 之后的 gameplay 阶段（`RemoveLife` 调用），postfix 无法捕捉。

**修复（3 部分，按调用顺序排列）：**

| # | 方法 | 位置 | 时机 | 作用 |
|---|------|------|------|------|
| 1 | `PrepareLocalWorkshopRejoin` | `WorkshopPlayer.cs` | `Player.Start()` 之前（TracePrefix 中） | 清除 `IDroppedOutThisRound`，恢复 `lives=1` |
| 2 | `PlayerStartPostfix` | `WorkshopPlayer.cs` | `Player.Start()` 之后 | 检查 `lives<=0` 时恢复为 1 |
| 3 | `RemoveLifePrefix` | `WorkshopPlayer.cs` | `RemoveLife()` 调用时 | 阻止 `lives<=0` 的异常扣命 |

**日志输出（按优先级）：**
- `"Restored local Workshop player life before Player.Start: player=X; previousLives=Y."`（PrepareLocalWorkshopRejoin 触发）
- `"Restored local Workshop player lives from 0 to 1 after level switch: player=X."`（PlayerStartPostfix 触发）
- `"Blocked RemoveLife for local Workshop player (lives<=0): player=X; lives=Y."`（RemoveLifePrefix 触发）

**文件：** `HarmonyDiagnostics.WorkshopPlayer.cs`、`HarmonyDiagnostics.Patches.cs`（注册）、`HarmonyDiagnostics.cs`（调用）
**双端测试结果：**
- 加入方重入后"能操作没死亡" ✅
- 房主跳关后仍会死亡 ❌（加入方活着，房主死了）
- 原因：`RemoveLifePrefix` 只阻止 `lives<=0` 的异常扣命，房主正常死亡时 `lives` 从 1 扣到 0 是正常流程，被放行了。房主死后没有正确重生到当前关卡。

### 8. 重入后地图素材丢失（看不见但存在）

**触发场景：** 加入方退出重入后，能看到关卡（关卡逻辑正常）但地图素材看不见——碰撞体存在（能站上去走）但 Sprite 渲染器不可见。

**根因：** Unity 的 Block 持久化系统：
```
Map.LoadArea() 检查 hasPersistedPastLevelLoad
→ 为 true 时复用 persistentForegroundBlocks 中的 Block 引用
→ 但这些 Block 引用指向已销毁的 GameObject（Unity 假空）
→ 复用后 Map.blocks 填入无效对象
→ Collider 在物理引擎中残留（碰撞体存在）
→ Sprite 渲染器已销毁（不可见）
```

**修复（2 部分）：**

| 调用点 | 清理内容 | 作用 |
|--------|---------|------|
| `ResetWorkshopStateForNewSession()` 中 | `hasPersistedPastLevelLoad=false`、`persistentForegroundBlocks=null`、`persistentBackgroundBlocks=null` | 会话开始时清理 |
| `ApplyWorkshopState()` 末尾（提取为 `ClearMapPersistentBlockState()` 方法） | 同上 | 每次 SwitchLevel 时清理 |

**日志输出：** `"Reset Map.hasPersistedPastLevelLoad for Workshop rejoin."`（会话开始）

**文件：** `HarmonyDiagnostics.Lifecycle.cs`
**双端测试：** 用户实测确认"地图素材没丢失了！" ✅

### 9. 房主退出重入后回到第一关

**触发场景：** 房主在跳关后的关卡死亡→退出房间→重新加入，角色回到第一关（有跳关机关的地图），与当前实际关卡不一致。加入方退出重入也回到第一关。

**完整根因链：**
```
ApplyWorkshopState 首次注入 → GameState.levelNumber = 0
关卡推进（SwitchLevel）→ levelNumber 不更新（仍为 0）
房主退出 → RoomInfo.RefreshInfo() → Steam Lobby levelNumber = 0
主机迁移（原加入方变新主机）→ OnHostMigration → refreshMachineSpecificsOnly=true → 不更新 levelNumber
原房主重入 → LobbyJoined_Callback → PullUpdatedInfo() → 读到 levelNumber=0
→ QueueLateJoin → _lateJoinLevelNumber = GetRoomInfoInt(room, "levelNumber", 0) = 0
→ TryStartLateJoin → SetFieldOrProperty(state, "levelNumber", 0) → 加载第一关
```

**修复：** `TryStartLateJoin` 中，只有 `_lateJoinLevelNumber > 0` 时才覆盖 GameState 的 `levelNumber`：
```csharp
// 修复前：
SetFieldOrProperty(state, "levelNumber", _lateJoinLevelNumber);  // 始终覆盖为 0

// 修复后：
if (_lateJoinLevelNumber > 0)
    SetFieldOrProperty(state, "levelNumber", _lateJoinLevelNumber);
else
    DiagnosticLog.Info("Late workshop join skipped levelNumber override: RoomInfo levelNumber=0; keeping current GameState levelNumber.");
```

**文件：** `HarmonyDiagnostics.WorkshopJoin.cs`
**双端测试：** 仍复现 ❌——因为 Lobby 中 `levelNumber` 恒为 0，条件覆盖 `_lateJoinLevelNumber > 0` 不满足，走 else 分支保留了 GameState 的 `levelNumber`，但 GameState 的 `levelNumber` 也是 0（首次注入时设的，后续没更新过），所以结果还是 0。
**未解决原因：** 需要更彻底方案——要么 Workshop 关卡推进时把 `levelNumber` 同步为实际关卡号，要么重入时从新主机 RPC 同步当前关卡号。

### 10. RemoveLife 补丁导致锁血假死循环

**触发场景：** 修复 7 中 `RemoveLifePrefix` 阻止了"最后一条命被扣"后，房主陷入循环：死亡→`RemoveLife` 被 prefix 拦截（return false）→ 不扣命→ 角色卡在危险位置（落坑/岩浆）→ 再次触发死亡 → 循环。约 15 秒一次，场景不断重载。

**日志特征：** 每 ~15 秒出现一次 `"Blocked RemoveLife for local Workshop player (last life): player=X; lives=1."`，中间无其他事件。

**修复：** 移除"阻止最后一条命"的逻辑（`lives <= 1` 分支），只保留阻止 `lives <= 0` 异常扣命。允许正常死亡让重生机制工作。

**修改前后对比：**
```csharp
// 修改前（导致锁血循环）：
if (lives <= 0) return false;  // 阻止异常
if (lives <= 1) return false;  // 阻止最后一条命
return true;

// 修改后（允许正常死亡）：
if (lives <= 0) return false;  // 只阻止异常
return true;
```

**文件：** `HarmonyDiagnostics.WorkshopPlayer.cs`
**双端测试：** 锁血循环消失 ✅（后续测试不再见 15 秒间隔重载）

## 未解决问题（3 项）

### U1. 房主跳关后仍死亡
- 表现：加入方活着，房主死着
- 根因：`RemoveLifePrefix` 放行了正常死亡（`lives` 从 1 扣到 0），房主死后没有正确重生到当前关卡
- 与其他问题的关联：房主死亡后不重生，导致关卡无法推进（`levelFinished` 卡住），最终触发重载循环

### U2. 房主/加入方退出重入仍回到第一关
- 表现：退出重入后角色回到第一关（有跳关机关的地图）
- 根因：Lobby 中 `levelNumber` 恒为 0（Workshop 不依赖原生关卡编号），Mod 条件覆盖 `_lateJoinLevelNumber > 0` 不满足，GameState 的 `levelNumber` 也是 0
- 需要：Workshop 关卡推进时同步更新 `levelNumber`，或重入时从新主机 RPC 同步当前关卡号

### U3. SwitchLevel 后 BroBase.Start() NRE 风暴
- 表现：每次切关后 `BroBase.Start()` 抛 NullReferenceException，随后 1000+ 次重复 NRE 在 `TrySpawnDrone()` 和 `Update()` 中
- 根因：原生角色初始化在 Workshop 场景切换时异常，`this.player` 或 `this.player.ValueOrchestrator` 为 null
- 影响：角色初始化失败后 `localPlayers` 可能为 0，关卡状态异常
- 状态：Mod 无法直接修复原生代码，但修复 5（注入修复）和修复 8（持久化清理）后可能减轻
