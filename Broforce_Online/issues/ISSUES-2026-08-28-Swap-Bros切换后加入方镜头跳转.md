# ISSUES-2026-08-28 Swap Bros 切换后加入方镜头跳转

## 状态

**本轮兼容修复实机复测未通过；修复代码及其构建已回退，当前代码中已无法查询该兼容实现。**

## 现象

联机会话中由房主槽位使用 `Swap Bros` 替换当前角色时，加入方镜头会突然跳到地图另一侧，离开房主端权威角色所在位置。

## 已观测事实

- 双端 Unity Inspector 均可连接，场景均为 `Test Evan2`，战役均为 `Bromandy_Ptr1`，关卡索引均为 `1`。
- 切换前双端活动玩家均为槽位 `0`，`Player` NID 均为 `60001`，Owner 均为 PID `6 JKChan (Server)`；房主端 `Player.IsMine=true`，加入方端为同一玩家镜像且 `Player.IsMine=false`。
- 切换前角色为 `BroHard`，双方角色和 `Player` 跟随位置均约为 `(2287.27, 632)`；双方 `/Main Camera` 的 `SortOfFollow.followPosLerp` 也约为 `(2287.27, 632)`。
- 手动触发后，双方 `Player.playerNum` 仍为 `0`、NID 仍为 `60001`、Owner 仍为 PID `6`，且双方 `Player.character` 均已绑定到新的 `BroLee`。没有观测到玩家槽位或 PID 被替换。
- 同一时点房主端新 `BroLee` 位于 `(2287.27, 632)`，加入方端新 `BroLee` 却位于 `(1672, 1207)`。
- 加入方 `Player.SmoothedFollowPosition` 随错误角色位置变为约 `(1672, 1203.84)`；加入方 `SortOfFollow.followPosLerp` 随后位于约 `(1737.14, 1142.45)`。房主端相机和跟随位置仍保持约 `(2287.27, 632)`。
- `SortOfFollow.followT` 在切换前后均为 `null`，`followMode` 均为 `Normal`。现象不是相机引用永久指向房主、旧角色或其它场景对象，而是原生相机正常消费了加入方 `Player` 镜像上的错误角色位置。
- 本机 Unity Inspector 的 UMM 日志接口返回 `UMM log file not found`；远端增量日志只有检查已销毁旧对象产生的 Inspector 错误，当前没有可用于根因判断的 `Swap Bros` 运行日志。

## 根因判断

已确认的直接原因是：`Swap Bros` 替换角色后，加入方绑定的新角色副本取得了错误的初始位置，`Player` 的平滑跟随位置和相机随后按原生逻辑追随该错误位置。因此镜头跳转是角色替换位置同步问题的结果，不是独立的相机目标错误。

当时的源码调用链审计判断为：Swap Bros 2.1.5 的 `API.SwapToSpecificBro` 先保存旧角色位置，并对旧角色调用 `SetSpawnPositon(..., TriggerSwapBro, ..., oldPosition)`；随后直接调用 `Player.SpawnHero`。它没有设置原生 `Player.changingBroFromTrigger`，所以 `SpawnHero -> WorkOutSpawnPosition` 不会选择 `TriggerSwapBro`，而会按普通存活玩家流程计算检查点/空投位置并向所有端广播。Swap Bros 最后只在拥有端调用 `newCharacter.SetPositionAndVelocity(oldPosition, oldVelocity)`，该直接恢复不会在相机读取新角色之前即时传给加入方。

因此加入方先收到并绑定新角色，再收到原生普通出生位置 `(1672,1207)`；`Player.SmoothedFollowPosition` 和相机随之跳转。拥有端的直接恢复以及稍后的状态/本项目既有延迟位置重广播最终把加入方拉回 `(2287,632)`，与 MCP 观测完全一致。

本轮实机复测未能证明仅通过补齐 `changingBroFromTrigger` 和首次权威位置交接即可解决问题。该调用链仍是已有证据支持的调查方向，但不能继续将本轮修复方案写成已验证根因闭环。

## 拟修复范围

- 只处理有效联机会话中由 `Swap Bros` 替换已有玩家角色时，新远端角色副本的首次权威位置应用。
- 以稳定的玩家槽位、PID、`Player` 与新旧角色关系识别事件，不使用某次运行的对象名、Instance ID 或地图坐标。
- 保留原有切换输入、英雄选择、角色所有权、NID 分配和后续网络状态同步。
- 只阻止新角色绑定窗口内由错误出生/回退位置造成的加入方镜头跳转，不修改一般重生、敌人、尸体、投掷物、拾取物、地图动态实体或其它相机行为。
- 添加克制诊断，至少对齐切换请求、旧/新角色、槽位/PID、相机旧/新跟随位置，以及是否阻止异常回退。

## 验收标准

- 双方完全退出并重新启动，加载同一个新构建。
- 加入方观察 `Swap Bros` 切换后，新角色首先出现在房主权威旧角色位置附近，镜头持续跟随该新角色且不跳到地图另一侧。
- 房主观察到的加入方角色与加入方本地控制角色在槽位、PID、角色类型和位置上保持一致。
- 旧角色被替换、死亡、销毁或失活时，相机不回退到出生点、房主或无关对象。
- 连续多次切换后，玩家槽位、PID、角色控制、角色位置和镜头跟随位置仍一致。
