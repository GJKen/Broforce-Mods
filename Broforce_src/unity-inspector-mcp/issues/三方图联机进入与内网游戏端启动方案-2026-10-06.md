# 三方图联机进入与内网游戏端启动方案

> 已验证日期：2026-10-08

## 结论

房主端三方图快速进入脚本 `quick-online-workshop.cs` 与加入端脚本 `quick-join-workshop-lobby.cs` 均已确认可用。本机也已经能够通过远程计划任务启动 5700G 上的 Broforce，并通过远程 Unity Inspector MCP 控制游戏。

当前推荐流程已经压缩为“启动目标端 -> 等待 Inspector 就绪 -> 一次提交快速进入脚本 -> 等待地图加载 -> 一次最终状态确认”。脚本调用本身是异步提交：返回成功只表示脚本已创建并开始运行，不表示地图已经完成加载；因此不能在脚本返回后立即连续轮询菜单状态。

进入地图后的清敌不再放在 MCP 关键路径中。已部署的 `TestMod` 会在游戏内检测到当前屏幕敌人后自动处理；标准流程不需要再调用 MCP 的 `KillVisibleEnemiesNow()`。只有需要补杀或验证公开 API 时，才单独执行该调用。

已验证结果：

- 本机触发远程启动返回 SUCCESS。
- 5700G.local:9999 TCP 端口连通。
- 远程 Unity Inspector ping 返回 pong。
- 远程游戏状态为 scene=MainMenu、isInGame=false、playerCount=0，说明游戏端已启动并等待后续流程。
- 三方图脚本此前已验证进入 Test Evan2，campaignName=Bromandy_Ptr1，playerCount=1，本地角色正常存活。

## 远程启动链路

~~~text
本机 MCP
  -> schtasks /S 5700G.local /U "5700G\\5700G" /P ""
  -> 5700G 上的 \\Broforce-AI-Launch
  -> C:\Users\5700G\Desktop\Broforce.url
  -> Broforce + Unity Inspector Mod
  -> 5700G.local:9999
~~~

不需要 SSH。远程 MCP 只连接 5700G.local:9999，远程启动失败时不会回退为启动本机 Broforce。

## 5700G 上的计划任务

5700G 的桌面快捷方式实际路径：

~~~text
C:\Users\5700G\Desktop\Broforce.url
~~~

在 5700G 上以目标用户打开管理员 PowerShell，使用以下命令创建或重建计划任务：

~~~powershell
$url = 'C:\Users\5700G\Desktop\Broforce.url'
if (!(Test-Path -LiteralPath $url)) { throw "找不到 $url" }

$taskName = 'Broforce-AI-Launch'
$runAs = (whoami).Trim()
$action = New-ScheduledTaskAction -Execute "$env:WINDIR\explorer.exe" -Argument ('"' + $url + '"')
$principal = New-ScheduledTaskPrincipal -UserId $runAs -LogonType Interactive -RunLevel Highest
$settings = New-ScheduledTaskSettingsSet -AllowStartIfOnBatteries -DontStopIfGoingOnBatteries

Unregister-ScheduledTask -TaskName $taskName -Confirm:$false -ErrorAction SilentlyContinue
Register-ScheduledTask -TaskName $taskName -Action $action -Principal $principal -Settings $settings -Force
~~~

计划任务的实际动作应为：

~~~text
C:\Windows\explorer.exe "C:\Users\5700G\Desktop\Broforce.url"
~~~

5700G 用户必须保持登录，并且存在可用的交互式桌面会话。锁屏可以；完全没有登录会话时，Steam、r2modman 或 Broforce 可能无法启动。

## 5700G 上的无密码账户策略

5700G 的本地账户没有设置密码。为了允许本机通过远程 RPC 使用该空密码账户，在 5700G 的管理员 PowerShell 执行：

~~~powershell
$lsaPath = 'HKLM:\SYSTEM\CurrentControlSet\Control\Lsa'
New-ItemProperty -Path $lsaPath -Name 'LimitBlankPasswordUse' -PropertyType DWord -Value 0 -Force
gpupdate /target:computer /force

$policyPath = 'HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System'
New-ItemProperty -Path $policyPath -Name 'LocalAccountTokenFilterPolicy' -PropertyType DWord -Value 1 -Force
~~~

确认值：LimitBlankPasswordUse=0，LocalAccountTokenFilterPolicy=1。

## 本机 MCP 配置

在 C:\Users\Administrator\.codex\config.toml 中配置远程 MCP：

~~~toml
[mcp_servers.unity_inspector_remote.env]
UNITY_INSPECTOR_HOST = "5700G.local"
UNITY_INSPECTOR_PORT = "9999"
UNITY_INSPECTOR_REMOTE_LAUNCH_HOST = "5700G.local"
UNITY_INSPECTOR_REMOTE_LAUNCH_USER = '5700G\\5700G'
UNITY_INSPECTOR_REMOTE_LAUNCH_PASSWORD = ''
UNITY_INSPECTOR_REMOTE_LAUNCH_TASK = '\\Broforce-AI-Launch'
UNITY_INSPECTOR_PROCESS_SCOPE = "remote"
~~~

注意：远程账户必须写成 5700G\\5700G，不能只写 5700G。密码保持空字符串。

## 从本机启动内网游戏端

先用 PowerShell 直接验证远程任务触发：

~~~powershell
$task = '\\Broforce-AI-Launch'
schtasks.exe /Run /S 5700G.local /TN $task /U '5700G\\5700G' /P ''
~~~

成功输出：SUCCESS: Attempted to run the scheduled task "\\Broforce-AI-Launch"。

验证远程端口：Test-NetConnection 5700G.local -Port 9999，结果应为 TcpTestSucceeded : True。

随后使用远程 MCP 的 ping，应返回 pong。确认远程连接后再调用 launch_game 或执行三方图脚本。

## 进入三方图

脚本位置：D:\Study\C#\Broforce-Mods\Broforce_src\unity-inspector-mcp\scripts\csharp\quick-online-workshop.cs

默认参数：workshopId=3715087178，playerLimit=3，sceneName=Test Evan2。

脚本会复用 CustomMapMultiplayer 的真实联机流程：

~~~text
DoHostGame -> CreateMatch -> newJoin -> AddLocalPlayer -> Workshop 地图注入
~~~

### 推荐调用时序

1. 先确定目标端：内网机器使用 `mcp__unity_inspector_remote__*`，本机使用 `mcp__unity_inspector__*`；同一轮不要混用两个端点。
2. 目标端未运行时只启动一次，并等待 Unity Inspector 连接成功。远程端使用已配置的 `Broforce-AI-Launch` 或远程 `launch_game`；本机使用本机快捷方式或本机启动入口。
3. 只调用一次 `quick-online-workshop.cs`，不要逐步调用 Arcade、Normal、Online、建房和地图菜单接口。
4. 脚本返回后不要立即连续读取 `game_state`、`list_enemies` 或截图。当前环境通常还需要约 8-12 秒的游戏内地图加载时间；在这段时间内不需要 MCP 介入，`TestMod` 会自行执行自动清敌。
5. 加载时间结束后只做一次最终 `game_state` 检查，目标为 `scene=Test Evan2`、`isInGame=true`、`playerCount>=1`。需要视觉证据时再取一张截图。
6. 如果最终检查仍处于 `MissionScreenVietnam`、`newJoin` 等过渡场景，不要回到菜单逐步操作；报告实际状态，只有用户明确要求继续等待或排查时才再次检查。

脚本返回 `success=true` 只代表异步 runner 已提交。真正的进入成功以最终状态检查为准。不要把脚本返回后的第一次过渡场景状态误判为失败，也不要为了等待地图而高频轮询。

## 本机加入 5700G 已创建的三方图房间

加入脚本位置：`D:\Study\C#\Broforce-Mods\Broforce_src\unity-inspector-mcp\scripts\csharp\quick-join-workshop-lobby.cs`。它和房主端快速创建脚本属于同一类异步 runner，但只负责加入已有 Steam Lobby，不会创建新房。

最短流程只有两步：

1. 在 5700G 房主端读取本次动态 Lobby ID：`SteamLayer.Instance.LobbySteamId.ToString()`。Steam 每次重新建房都可能生成新的 ID，因此不得硬编码。
2. 在本机 `mcp__unity_inspector__execute_script` 执行加入脚本，只传 `args={lobbyId:"刚读取的 Lobby ID"}`。脚本默认目标为 Workshop `3715087178` 和场景 `Test Evan2`。

脚本先校验 Steam Lobby 的 Workshop 身份、场景、游戏网络版本和容量，再调用原生 `SteamLayer.JoinLobby`。CustomMapMultiplayer 继续负责晚加入地图加载和本地角色生成。提交后等待约 8–12 秒，只做一次本机 `game_state` 检查，再做一次房主端检查。2026-10-08 实测中，本机作为 P2 `BroGummer` 加入 5700G 的 P1 `Desperabro`，双端均进入 `Test Evan2 / Bromandy_Ptr1` 并显示 `playerCount=2`。

### TestMod 配合

`TestMod` 的自动击杀开关必须按本轮测试需要设置。开关开启时，进入 `Test Evan2` 后由 Mod 自己在游戏帧内检测并清除当前屏幕敌人，AI 不应在地图加载后再等待 MCP 调用清敌。需要手动补杀时才调用：

~~~csharp
TestMod.Plugin.KillVisibleEnemiesNow()
~~~

调用返回值是实际处理的敌人数量；开关关闭、Mod 未启用、地图尚未完成加载或当前没有可见目标时都可能返回 `0`。禁用或查询开关使用 `TestMod.Plugin.SetAutoKillEnabled(false)` 和 `TestMod.Plugin.IsAutoKillEnabled`。

不要用 LastTaskResult=1 单独判断游戏启动失败。本方案以远程任务触发返回 SUCCESS、9999 端口连通和 Unity Inspector ping=pong 作为启动成功依据。
