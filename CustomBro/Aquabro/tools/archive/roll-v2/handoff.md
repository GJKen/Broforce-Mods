## 实际取帧与时序

帧序依据上述反编译文件的实际调用链，不使用旧帧号表推断。

1. `Land()` 第 7710–7734 行：存活角色落地时只按住一个左右方向键，在 `useNewFrames` 开启且 `CanDoRollOnLand()` 成立时调用 `RollOnLand()`。后者的条件为 `doRollOnLand && yI < -350f && skinnedMookOnMyBack == null`，见第 7790–7792 行。
2. `RollOnLand()` 第 7795–7797 行只设置 `rollingFrames = 13`。随后 `Land()` 清零 `counter` 并直接调用 `AnimateRunning()`，由其翻滚分支调用 `AnimateRolling()`。这次没有经过 `ChangeFrame()`，所以首格 **51 会显示**。
3. `AnimateRolling()` 第 3979–3987 行设置 `frameRate = 0.025f`，取第二行的 `19 + (13 - rollingFrames)` 列，并调用 `DeactivateGun()`。身体格为 `32 + 19 + (13 - rollingFrames) = 64 - rollingFrames`。
4. 常规更新第 2029–2034 行执行 `counter += t`，在 `counter > frameRate` 时减去一次间隔，调用 `IncreaseFrame()`、`ChangeFrame()`。`ChangeFrame()` 第 4581–4583 行先递减 `rollingFrames`，再分发站立或跑步动画，因此之后依次显示 **52–63**。
5. 计数从 1 减到 0 后，站立/跑步分支不再进入 `AnimateRolling()`，恢复相应普通动作及武器。不会继续取翻滚第 14 帧，也不应把 64 格纳入本组。
6. `rollingFrames == 7` 时调用 `PlayRollLandSound()`，对应源稿第 7 帧、身体 57 格、名义时间 150 毫秒。这里只记录回调位置；所读基类中的该回调为空方法。

源稿严格使用 **25 毫秒/帧，13 帧共 325 毫秒**。这表示未打断路径的名义间隔；游戏以 Update 的 `t` 推进，判断是 `>` 且每次只推进一次，实际显示受更新步长、状态切换及额外 `ChangeFrame()` 调用影响。Aseprite 源稿时长不会改写游戏代码。

当前 `Aquabro.CanPlayLandingAnimation()` 要求 `rollingFrames <= 0`，因此普通落地三帧不会覆盖翻滚。`RunFiring()` 在有效攻击输入时调用 `StopRolling()`；本次保留该取消逻辑。`rollingTime` 使用的另一套动作没有纳入本组。

原版翻滚结束不会专门把普通跑步计数重置为首帧；实际恢复哪一跑步相位仍由原版决定。本次保留兰博第63格原版起身姿势，不再用run-v3首帧替代它。
