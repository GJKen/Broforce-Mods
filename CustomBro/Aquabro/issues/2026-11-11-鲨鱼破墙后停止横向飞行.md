# 鲨鱼破墙后停止横向飞行

日期：2026-11-11。状态：第二轮补修已部署至项目及本机两处角色目录，用户亲自实机验收通过；发布包已更新，5700G 未同步。两轮修复已合并为同一条本地提交，尚未推送；`ba61e39` 为合并前的首次修复提交。

## 首次修复的现场与原因

`Test Evan2` 暂停现场，起跳水花固定在 X=1215.567，鲨鱼本体仅前进到 X=1216。前方 `(1232,144)` 的 `Hell Brick4(Clone)_77_9` 已为 `health=0`、`destroyed=true`、碰撞关闭；其最后伤害记录为 Aquabro 的 28 点 `Crush`，说明已被鲨鱼打碎。

`TickSharkBreach` 在运动碰撞限制横向位移后立即将 `sharkVelocityX` 永久归零；同一子步随后执行的 `SkillSharkObjects` 即使打碎阻挡砖块，后续也不再恢复横向飞行，因此出现前方已空却停住的表现。

上方 `(1216,160)` 仍有完整砖块，低顶依然可能限制上升；第一次只修复破墙后横向不恢复，没有改变顶碰撞，随后用户复测确认仍会被阻挡。

## 首次修复与验证

- 保留起跳横速，每个子步继续通过原有碰撞扫掠限制实际位移；完整墙体仍阻挡，路径清空后恢复原速，顶碰撞终止上升，落地停止运动。
- 新增双朝向、15／30／60／120 FPS 用例，检查实墙阻挡、移除墙后暂停不推进、恢复时按原横速移动。旧源码在恢复断言上失败，修复后通过。
- `Build-Wave.ps1` 编译通过，DLL 仍为 93,696 字节，保留 3 条既有 CS0253 警告；当前生产源码与正式 PNG 的四技能综合回归通过，进程退出码为 0。
- 确认 Broforce 进程退出后，更新项目 `_Mod`、本机 `BroMaker_Storage/Aquabro` 与 `CustomBro/Aquabro/_Mod` 三处 DLL，读回 SHA-256 与构建产物一致；贴图与蒙版未变。
- MCP 现场诊断发生于部署前；新 DLL 部署后未重启实机复测，不据此宣称实机或联机验收通过。临时只读诊断脚本已卸载并删除，游戏已关闭。
- 先前血水遮挡修复单独提交为 `3af9cb5`，现已推送；首次鲨鱼修复当时单独本地提交为 `ba61e39`，当前已按用户要求将第二轮修复合并进同一提交，尚未推送。

## 用户复测后的第二轮补修

### 补充原因

确认游戏实际加载首次修复 DLL（93,696 字节，MVID `bc9c56c1-02b9-43a1-90b8-130045fc501f`）后，在 `Test Evan2` 从 `(1215.567,88)` 按 1/120s 推进生产鲨鱼实例。约 0.0583s 时竖速已降至 -16.67，约 0.179s 就落地于 X=1229.778，仅前进约 14.21px。

- 顶碰撞固定探测锚点上方 56px，而起跳第 28 帧本体最高仅约 20px，身体尚未触顶就终止上升。
- 横向碰撞和地形破坏没有使用同一接触依据：身体像素碰到砖边角时，旧物件路径仍从任意 Y+48 高度发水平可见性射线，可能被相邻砖块遮住，造成阻停却未破坏实际接触砖块。
- 因此，仅保留横速的 `ba61e39` 不足以解决现场问题。上述轨迹属于补修前的诊断结果。

### 实现与回归

- `MoveSharkFlight` 的横向及上升碰撞改用当前帧 `SkillContactMask`，沿用本体可见像素与 5px 余量；先尝试破坏接触地形，再判断是否仍阻挡。拆砖暴露其它接触砖时，在阻挡数量减少期间继续处理，避免物理结果顺序造成漏拆。
- `PixelMask.IntersectsRect` 增加接触点可见性回调，`SkillContactMask.IntersectsVisibleRect` 将真实像素接触点转换到世界坐标；鲨鱼 collider 伤害从本体内的 `(X,Y+8×Scale)` 向该点检查遮挡。保留实体墙与水线下支撑保护。
- 下落接地继续使用原地面射线；不可破坏墙顶仍阻挡，落地停止运动。起跳横速、240px/s 竖速、800px/s² 重力、28 点伤害及拥有端规则保持原值，PNG、生成蒙版、JSON 与版本号未改。
- 新定向回归在旧生产代码上因 56px 提前撞顶断言失败，补修后通过。真实 16px 可破坏低顶砖块下，双朝向、15／30／60／120 FPS 均能破坏接触砖并完成约 64px 飞行；同时覆盖不可破坏屋顶／地板、实墙阻挡与移除恢复、暂停。
- 四技能综合回归通过，退出码 0；`Build-Wave.ps1` 正式编译通过，保留 3 条既有 CS0253 警告。DLL 为 94,208 字节，比首次修复增加 512 字节；`Release/UMM/BroMaker_Storage/Aquabro/` 与 `Release/Aquabro.zip` 已随构建更新。

### 部署与验收

确认 Broforce 退出后，部署到项目 `_Mod`、本机 `BroMaker_Storage/Aquabro` 与 `CustomBro/Aquabro/_Mod`，三处均确认没有 `.dll.cache`。重新启动游戏后，用户亲自验证并明确反馈“这次才是没问题了”，据此记录本次实机验收通过；代理没有完成新 DLL 下原位置的轨迹对照，不将旧版诊断记作新版验证。未进行本轮双端联机或所有地图完整验收，5700G 未部署本次修复。
