# 2026-10-19 蛞蝓头部兼容修复

MCP 在 测试战役关卡第五关、`测试场景` 场景确认：头部 `BossSlugFace` 不继承 `Unit` 或前三类 Boss 部件。原运行版本（标识已脱敏）中，真实头部代理无法被 `BossDamageTarget.Find` 识别；四技能像素均接触时，狂潮误走物件分支提交 24 点 `Crush`，鲨鱼对两个代理各提交 28 点 `Crush`，漩涡／涌泉没有头部请求。诊断拦截了扣血，头部保持 422 点血，暂停状态未改变。

本轮将 `BossSlugFace` 纳入公共部件识别，按最终头部对象共用命中记录，实际伤害仍经过碰撞体上的原版代理与 `BossSlugFace.Damage`。狂潮恢复 26、鲨鱼 28 且多代理只提交一次、漩涡脉冲 3／收尾 9、涌泉每次 4／最多七次；普通／蓄力直击和水花同时接入该识别。保留头部死亡／零血、代理关闭／销毁、原版帧内防重复和阶段行为，不强制位移头部。

`BossSlugPiece.Damage` 原本为空，身体装饰与坍塌结构不映射为可扣血头部；第二阶段 `BossSlugHeart : BossWeakSpot : BossBlockPiece` 沿用既有弱点处理。

`Test-Spring.ps1` 与 `Test-WaterBlastZones.ps1` 已通过。新增回归涵盖四技能、直接／多个代理、左右与缩放、关闭后恢复和死亡过滤；普通／蓄力完整弹丸扫掠不重复结算；30/60/120 FPS 下头部涌泉总预算 28、漩涡总预算 36。模型不提供帧内防重复，验证生产逻辑自身的命中去重。

`BuildAssets.ps1` 构建与部署通过，两个游戏目录的 DLL SHA-256 均与项目产物一致：校验值已脱敏。当前运行版本已脱敏，重启后确认实际加载该版本。编译有三条既有 `CS0253` 引用比较警告，没有编译错误。

最后尝试用`tests/Probe-SlugHeadHealth.cs` 在原关卡验证真实头部扣血，但遭遇 MCP 代码／脚本执行超时，未取得可用扣血结果，不能记为实机扣血通过。已卸载诊断脚本并再次重启，清除临时运行状态，重新进入同一蛞蝓关卡。当前证据为离线回归通过、磁盘部署一致和新版本加载确认；实际实时扣血、完整战斗、第二阶段推进及远程联机仍待验收。
