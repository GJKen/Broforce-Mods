# Aquabro 自动精简使用说明

配置日期：2026-10-23。适用于本机 Codeg 0.39.0，使用其 codeg-cli 新建 Codex 对话并收集结构化结果。当前目标已改为减小最终 Aquabro.dll 的实际字节数，同时保持原机制。

## DLL 体积目标与门槛

- 每轮最终 DLL 至少比本轮快照减少 512 字节。相同体积、变大、仅减少源码行数或仅减少运算次数都不保留；同一功能的相关调整合成一轮测量。
- 优先检查大块内嵌数据的无损表示、重复代码和可证明无用的私有代码。所有数据仍内嵌 DLL，不通过额外依赖或外部文件转移体积，也不降低像素精度或删除功能。
- 控制器直接读取旧、新 DLL 字节数；同正式编译器和正式参数分别复编译基线与候选，核对体积一致。正式构建已开启优化、关闭调试信息，不允许修改编译参数制造差异。
- 每轮成功方案都须从旧、新游戏实际程序集导出五类蒙版，完整比较尺寸、帧数及所有帧字节。允许修改指定生成器及模板以实现无损存储，动画、碰撞规则、PNG 和 JSON 保持原样。
- 状态显示本批次初始体积、当前体积和累计减少字节；每轮历史及报告记录前后字节数、减少字节和比例。旧批次历史继续保留，不算作新的体积收益。

切换目标时 DLL 为 761,856 字节，元数据字符串区为 676,500 字节，主要调查方向是以 Base64 字符串保存的蒙版。这是基线分析，不代表压缩已完成或承诺缩减幅度。体积未达到门槛按失败方案处理：回退、换方案；该候选无可用方案则跳过，继续找其他候选。

## 日常操作

每轮新对话（包括失败后换方案的重试）都通过 Codeg CLI 显式传入 --effort max，不再继承应用默认的 low。模型仍沿用当前 Codeg 设置。

提示词通过UTF-8标准输入传给Codeg（--prompt -），本轮完整内容仍保存为prompt.md，避免历史和失败原因增长后超过Windows命令行长度限制。会话未按schema提交JSON时，先恢复该轮，再另开对话重试；连续三次基础设施失败则保留已验收成果并在状态中显示具体原因及rejections.json位置。

- 桌面的「Aquabro 自动精简-启动」：后台开始一批任务，已经运行时不会重复执行。
- 桌面的「Aquabro 自动精简-状态」：查看当前阶段、轮次及 Codeg 会话入口。
- 桌面的「Aquabro 自动精简-停止」：请求取消当前轮；确认代理退出后恢复该轮开始时的源码及部署，已经验收的轮次保留。
- 启动后每轮都会出现在 Codeg 对话列表。Codeg 与电脑需要保持运行；关闭当前聊天不影响后台控制器。不设置开机启动或定时任务。

也可在仓库内用 PowerShell 操作：

    ./CustomBro/Aquabro/tools/auto-optimize/Start.ps1 -Action start
    ./CustomBro/Aquabro/tools/auto-optimize/Start.ps1 -Action status
    ./CustomBro/Aquabro/tools/auto-optimize/Start.ps1 -Action stop

## 每轮执行与验收

1. 关闭游戏，备份本轮实际工作区和两处部署目录中的运行文件。未提交改动同样属于基线，不回到 Git 提交版本。
2. 新建独立 Codeg 对话，按预期节省字节选择候选。修改生产代码前先上游戏，记录真实角色、场景、程序集 MVID、DLL 哈希、完整蒙版、受影响机制与原始检查输出。
3. 修改后执行离线回归；先彻底关闭游戏，再构建部署。新进程上游戏读取新程序集，复测同一机制及相关边界。
4. 达到 DLL 体积门槛、完整蒙版和前后机制一致才新建 docs 轮次报告。外层控制器另行核对实际体积、正式参数复编译、证据、部署哈希并独立执行五组既有回归；失败方案不保留。
5. 验收通过自动开始下一轮新对话。连续两轮独立检查都没有达到体积门槛且可保持机制的候选时结束。

## 失败后如何处理

验证失败不是立即终止：恢复当前方案，再分析原因、尝试不同实现；每个候选最多尝试三种合理方案。可用方案均失败或不适用时放弃该候选，恢复其源码和部署，新开对话寻找别处。外层验收失败也最多另开三次会话重试，并交接失败原因。

不得改变玩法数值、时序、判定、所有权、去重、输入交接、生命周期、动画、伤害路由或联机语义，也不得放宽测试来通过验收。实机只证明已覆盖的场景，无法可靠验证的候选不应修改。

Codeg、构建或游戏工具持续不可用属于环境阻碍：恢复本轮后报告阻碍，避免无效循环。若尚未确认代理退出，不能同时回退；保留备份并在状态中说明，避免覆盖仍在写入的进程。

## 记录与恢复

- 控制器与单轮规则：tools/auto-optimize/controller.py、round.md、round.schema.json。
- 运行状态：archive/auto-optimize/status.json；历史：同目录 history.json。
- 每批次、每轮快照、尝试、前后实机证据、原始输出与独立回归日志都在 archive/auto-optimize 下，保留失败证据用于下一方案。
- 通过验收的体积变化和源码微优化统一登记在 [自动精简历史](自动精简历史.md)；主要 DLL 体积变化保留独立技术报告。本文只说明自动化操作，不代表某项代码精简已经通过。
- 不提交或推送 Git，不修改其他插件。开始前已有未提交工作按实际字节备份保留。

运行期间不要同时手动修改 Aquabro，也不要启动另一轮构建或实机检查；需要手动工作先用停止入口等待回退完成。强制杀控制器可能使代理仍在运行，此时先查看状态、Codeg 会话及备份，不能直接删除锁文件后重复启动。
