## 普攻判定与场景接口

### 投掷与蓄力计时

普攻由自定义 `RunFiring()` 在松键时出手，`UseFire()` 为空。实际投掷冷却取常量 `ThrowCooldown=0.2s`，满蓄力阈值取 `FullChargeDuration=0.5s`；冷却期间不累计下一次蓄力。配置的 `fireRate` 和原版 `TimeBetweenShots` 不直接控制这两个时长，调整实际投掷间隔应修改 `ThrowCooldown`。

`RunFiring` 在死亡、近战、失能、直升机运输、投掷手持物、被刺穿／捆绑／寄生／酸液覆盖、特殊动作及手势期间清零 `chargeTime`、`throwDelay`、`throwCooldown`，不缓存待补发投掷。动作结束后若仍按住攻击，从零累计；只有有效蓄力大于零且松键才出手。切换技能入口也立即清掉蓄力与收招。普通三叉戟仍沿用 `PredabroSpear` 的弹丸碰撞入口，可能先撞到可受伤的敌方火箭而起水花，火箭反应由其原生受伤规则决定。

### 戟尖扫掠与贴身命中

视觉戟尖约在弹体坐标前方 24px。每次单位检测扫掠上一检测位置到当前戟尖之间的轨迹，选最先接触的有效活敌，避免高速飞行跳过敌人。

首次检测时，如果弹体仍在角色前方 0–40px 内，从角色身体横坐标开始扫到戟尖，补齐出生点前方 14px 造成的贴身盲区；首次观察到已飞远或在身后的弹体，则从弹体位置起扫，不把远处弹体的路径补回身体，也不向角色身后扩伤害。

敌人检测横向使用身体半宽 `width/2`；角色型目标的顶部使用当前 `headHeight`，其他单位顶部使用 `Y+height×2+3`，再在上下各留 3px 戟尖接触余量。命中点夹在目标脚底与实际顶部之间，兼容蹲姿和重装兵头部。排除自己、尸体、无敌单位及游戏规则不允许攻击的目标。

戟尖扫掠同时检查沿途实体墙，先碰到墙就撞墙起水花，墙后敌人不会被登记为直击；墙前的敌人仍可先命中。触发器、单位身体和 Boss 单位部件不当作普通墙体。普通／蓄力均适用，包含贴身补扫和高速飞行。原版出生检查若先在墙内触发命中特效，会将爆心移回迎面墙外 0.05px，避免从墙内绕过遮挡。

首次实体接触即在接触点触发水花。每支戟只结算一次水花并销毁，不连续穿透制造多次水爆。直击与周围范围伤害合并为同次水花的一次目标结算：直击伤害为 `max(长矛 damageInternal, 普通8／蓄力14)`，不因目标的脚底采样点离爆心较远而变成零伤害，也不会额外叠加一份独立直击伤害。

游戏里不会出现原版长矛插墙后供角色踩踏，或串着小兵继续飞的效果：海王的接触处理替换了这两种原版行为，命中后直接起水花并销毁投掷物。四技能创建的水体也不提供实体立足面，不能踩水柱或浪头借力。

### 普通水花与蓄力水爆

| 项目 | 普通水花 | 蓄力水爆 |
| --- | --- | --- |
| 范围形状 | 以敌人 `(X,Y+6)` 采样点计算圆形距离 | 敌人身体矩形接触当前帧可见水花；透明部分不算，直击目标另有保底 |
| 伤害半径 | 12px | 可见接触点距爆心不超过 25.2px（72÷2×70%），造成 14 点伤害 |
| 外围冲击 | 无额外外圈 | 25.2px 之外仍碰到当前帧可见水花，仅震飞，伤害为 0 |
| 伤害类型 | `Melee` | `Explosion` |
| 检测时机 | 起爆立即一次 | 立即一次，之后在 600ms 内持续检测后来进入的活敌 |
| 防重复 | 同一水花每敌一次 | 同一水爆每敌一次，先进入外圈后进入内圈不补伤害 |
| 画面 | 48×48，12 帧，共 540ms | 64×64 源帧显示为 72×72，6 帧，共 600ms |

蓄力水花碰到敌人头部、身体边缘或脚部都能生效，身体边界采用当前 `width` 与 `headHeight`，非角色单位采用自身高度。判定与当前显示帧一致，只取非透明像素；按 72×72 显示大小换算，不把透明画布当水体。可见水花与身体的重合部分中，只要存在无遮挡且距爆心不超过 25.2px 的接触点，就按内圈结算；仅接触外围则只震飞。该 70% 以显示画幅半宽 36px 为基准，画面边角的可见水滴也可触发外圈冲击。

透明处、未接触和墙后的目标不会提前登记，后续进入仍有一次机会；已经在外圈被零伤震飞的目标已计入本次命中记录。蓄力检查爆心到实际水体／身体接触位置的实体墙遮挡；普通水花仍检查爆心到 `(X,Y+6)` 的遮挡。完整墙后的目标不受伤、不震飞，也不消耗本次命中机会。墙被摧毁后，仍在 600ms 有效时间内的蓄力水爆可以命中恢复无遮挡的目标。只伤害有效活体；不存在残留水洼、减速或动画结束后的持续伤害。

普通水花横向冲力为远离爆心方向的 110，向上 90，爆心重叠时用投掷方向决定左右。蓄力冲力按目标相对爆心方向分配：横向为 `dx/距离×400`，中心重叠时为投掷方向 100；竖向以 `dy/距离×400+260` 为基础，并至少为 `max(260, abs(横向冲力)+40)`。最终击退、翻滚、后空翻和抗击退由目标原版逻辑处理，不修改 `canTumble` 等属性。

动画帧段与导出输入见 [普攻特效](../aseprite-source/06_普攻特效/Readme.md)。

### 地形、物件、弹丸与声音

命中时以弹体当时的水平速度判断普通／蓄力：`abs(xI)>500` 为蓄力，否则为普通，不仅依赖按键时长或贴图。

- 普通碰地：拥有端先调用 `DamageGround`，伤害取长矛 `damage`，类型 `Crush`、范围参数 16px（接口实际查询半径为 8px），位置沿碰撞法线向外偏 3px，再触发水花。直接撞到 Boss 部件时改走下述部件直击流程。
- 普通物件：使用长矛 `damageInternal`、原长矛伤害类型与速度，半径参数为 8px。
- 蓄力破土：起爆时调用一次 `DamageGround`，基础 14 点 `Explosion`，范围参数 18.2px（接口实际查询半径为 9.1px）。
- 蓄力物件：起爆时调用一次物件伤害，基础 14 点 `Explosion`，半径参数为 18.2×0.6=10.92px，冲力参数为 0；物件接口内部规则仍由原版处理。
- 蓄力弹丸：只检查敌方可受伤投射物，其**中心**位于 18.2px 圆内时施加 14 点爆炸伤害；这可以触发弹丸自身的受伤／爆炸反应，与水技能直接熄灭弹丸不同。
- 蓄力摇树：矩形接口使用圆的内接正方形，横竖范围各约 18.38px（26×0.70710678），强度 60。

上列场景破坏、弹丸与震屏仍采用各自原有半径，不随本次单位接触范围扩大。上述地形、物件、弹丸和摇树只在起爆时结算，不会随 600ms 动画重复执行。单位检测则继续到动画结束。普通水花后续动画仅显示。

物件使用 `DamageWaterDoodads` 保留原版 `Map.DamageDoodads` 的范围、敌我免疫与 `DamageOptional` 入口，并在受伤前检查爆心到物件中心的实体遮挡；蓄力弹丸伤害同样检查到弹丸中心的遮挡。`WaterSceneContactVisible` 使用终点前 0.01px 的完整射线，忽略触发器、单位／单位代理，以及接收者自身和子碰撞体。物件与弹丸的墙后保护不再依赖只针对单位的水花判定。

场景受伤对象共用通用碰撞入口，已知 `BossPiece`、`BossBlockPiece`、`BossBlockWeapon`、蛞蝓头部 `BossSlugFace`、撒旦浮动头部 `BossSatanFloatingHead` 与手臂 `BossSatanArm`（含代理转发）单独按碰撞体接触处理，普通使用 `Crush`，蓄力使用 `Explosion`。部件直击同样取 `max(damageInternal, 普通8／蓄力14)`；普通范围按 12px 圆与部件矩形接触，蓄力范围按当前 72px 水花的可见像素与部件矩形接触，内圈基础 14 点，外圈不扣血也不强制震飞 Boss。蓄力后续帧仍可命中后来接触内圈的部件。地形接口忽略这些部件，直击、范围和关联部件共享命中记录，避免另叠一份破土伤害。

蓄力震屏只由拥有端触发，且角色 `(X,Y+6)` 距爆心必须小于 26px，强度为 `0.2×(1-距离/26)`，不产生远距离全屏震动。攻击使用 Predabro 的声音资源，投掷会惊动角色周围 120px 内的野生动物。

### 近战与丢兵

近战丢兵：自定义前刺不经过 `BroBase.AnimateMeleeCommon`，需在 `RunFiring` 的前刺命中时刻、`PerformKnifeMeleeAttack` 之前保留原版 `highFive && nearbyMook != null && nearbyMook.CanBeThrown()` 检查。满足时先 `CancelMelee()`，再 `ThrowBackMook(nearbyMook)` 并清掉 `nearbyMook`，立即返回，避免同帧补出前刺或低帧率结束流程。附近目标仍由原版 `PressHighFiveMelee`／`FindNearbyMook` 选取，丢出姿态、释放速度及手雷优先由原版处理；无需修改素材。

## 四技能的更新与地形探测

切换接在原版按键上升沿调用的 `SetGestureAnimation(Flex)`。`TriggerFlexEvent` 在原版流程触发两次，不能作为单次切换入口。起手固定本次技能；第 3 施法帧（索引 2，约 130ms）释放，身体每帧 65ms。狂潮 6 帧，其余源稿 8 帧；猎杀成功生成后立即退出人物施法，起手和释放时均检查支撑。

`originalSpecialAmmo=5`，四技能共用原生 `SpecialAmmo` 消耗与补给。切换只更新选择、图标并清掉普攻蓄力，不重置次数，也不清理已有技能或敌人的原生酸液状态。切换仍要求角色存活、可行动、未在施法／近战或遥控鲨鱼；鲨鱼跃出后可切换并释放其它技能，仅新一只鲨鱼需等旧实例结束。

`UseSpecial` 在实际释放时只扣一次，技能没有找到敌人或随后没有命中也不退还。狂潮、漩涡、涌泉可以继续生成独立实例，重叠时各施法的命中记录和伤害预算独立；涌泉仅同次七柱共享预算／污染。猎杀在起手及实际释放时都检查支撑，释放前失去支撑会取消且不扣次。零次数时只闪烁 HUD；重生、补给继续走原生特殊次数流程，Utility Mod 等全局无限技能设置可另外干预耗尽行为。

| 技能 | 尺寸、帧段与探测 |
| --- | --- |
| 狂潮 | 缩放 0.85；水平最多 8px 小步。0–2 帧各 0.1s 起浪，3→4→5→4 各 0.1s 循环；6–15 帧各 0.05s 消散。地形每 0.12s 提交 24 `Crush`，水线下支撑受保护；高于水线 8px 的存活实体障碍可阻停。 |
| 猎杀 | 潜行按最多 4px 小步移动，在水线上方 4px 探墙、墙前留 4px；支撑包含 `LargeObjects`。空中使用独立本体图集的 28–58 格，按 60Hz 播放补间姿态；实际落地后切回校准后的合成图，播放 19–27 帧入水，每帧 0.05s，槽 19 只有本体，槽 20 开始起水。 |
| 漩涡 | 缩放 0.85；水平探测高度 12px／56px，最多 4px 小步、墙前留 8px。0–4 帧各 0.05s 起势，5–23 帧各 0.07s 循环，24–31 帧各 0.075s 消散。 |
| 涌泉 | 横向预定偏移 -90／-60／-30／0／30／60／90px；中柱从 Y+12 向下找 55px，两侧最多 4px 小步，上台阶最多 16px、向下找 43px，无地保留上一高度。最外两柱缩放 0.9，其余 0.65；0–17 帧有效，18–27 帧消散，每帧 0.05s。 |

猎杀的潜行恐惧每约 0.3s 检查一次：有效活敌、`playerNum<0`、横向 64px 内、脚底处于水线 -4～+36px 且无遮挡，惊慌 0.6s，可刷新。遥控寿命读取 `Dredd.specialRocketPrefab.life`，资源无效时回退 4s。镜头在跃出开始时立即交回人物，原生 `controllingProjectileDelay` 至少 0.25s，保留已有更长值。

潜行松开左右键或同时按左右时停止，单向输入会更新鲨鱼朝向；跃出沿最后朝向飞行，之后不再接受遥控转向。特殊键保留原版按下沿判断，持续按住首次施放键不会直接触发跃出。潜行找地使用无限向下射线，有底深坑会直接更新到坑底高度；向下输入只绕过梯子支撑，不穿过实体地板。无底时保留上一处安全支撑位置。

跃出本体从当时的 `(x,y)` 水线起飞，初始竖速 240px/s、重力 800px/s²，横速 `64/(2×240/800)≈106.67px/s`；同高无障碍飞行约 0.6s、64px，最大高度 36px（本体锚点）。`TickSharkBreach` 使用不超过 1/120s 和约 4px 路程的子步，步内按解析重力积分。`MoveSharkFlight` 只扫掠本步真实下降区间；不会在跃出时用无限向下射线把本体放到坑底。横向仍保留 12／56px 探墙和 8px 间隔，撞墙停止横速；顶部碰撞终止上升后继续下坠。无底洞最多飞行 4s，实际落地后才开始 0.45s 入水收尾。每子步以当前本体蒙版结算，同次目标仍只受击一次。

本体 `skill-shark-hunt-body.png` 取源稿第 1、2、4、5、6 层，尺寸为 7552×128、共 59 格。前 28 格中的 19–27 格身体在导出时统一下移 3px：源第 19 格鼻尖像素下沿为 109，距水线 112 尚差 3px，导出器据此自动计算偏移，令鼻尖触水与落地判定一致。后 31 格为 60Hz 空中补间：原姿态 6–15 按 30ms、15–19 按 50ms 连续推进，取相邻本体的主轴角度插值，以最近原姿态作小角度旋转并匹配插值中心。完整本体的竖向重心固定到校准后的第 19 格重心，消除素材自带弧线；不再逐格用变化的外接框底边定位。最后空中格与校准后的第 19 格本体逐像素一致，避免切进入水时跳位。全部 59 格的伤害蒙版直接由对应本体 PNG 生成。

第 3 层和第 7、8 层分别导出 `skill-shark-hunt-water-back.png`／`skill-shark-hunt-water-front.png`，均为 3584×128。`SharkSplashVisual` 只在起跳坐标播放完整 6–18 帧，固定世界坐标；人物移动或转身不会拖动／翻转水花。两层位于 Z=1.05／0.95，本体为 Z=1。鼻尖接触水面时，主体位置停止移动，材质切回 `skill-shark-hunt.png`，整帧播放校准后的 19–27 格；水花不作位移，原稿第 3 层仍位于尾部／身体与头部之间，由 Aseprite 原层序合成。已删除 `SharkTerrainWater` 的逐列支撑裁切、逐帧纹理复制及上传，两处水花均不再按地形删像素。

`SkillSharkObjects` 只在飞行尚未接触地面的子步执行，进入水面起停止普通地形和 Doodad 的这条伤害路径。`SkillSharkBlast` 仍在入水期间执行，因此敌人、Boss 以及由共用碰撞入口识别的箱桶、牢笼和锯齿仍可能受击，不能概括为入水后停止所有物件伤害。伤害使用与导出身体一致的本体蒙版，整次共用一次 28 点命中预算；水花不参与伤害。入水索引 19–26 可命中，索引 27（最后约 0.05s）仅播放画面，不再造成伤害。

入水槽 19（接触后最初 0.05s）只显示完整本体，不显示源稿此格残留的两段水线；完整图和分层水花图均在导出时省略该格水层。槽 20 开始身体没入水面，才播放入水水花，后续全部水花像素和层序保留。这与鼻尖的 3px 坐标校准分别处理接触位置和起水时机，不能仅凭鼻尖间隙为零断定水花画面正确。

漩涡自动定位选角色前方有效、存活的敌方 Unit，不再只限 Mook，坦克、机甲等也能作为落点目标：水平不超过 180px、高差不超过 96px、按二维距离最近、无遮挡且脚下 80px 内有支撑；排除自身、无敌及游戏规则不允许伤害的目标。持续吸力作用于 Mook 及其仍在场的完整尸体，不作用于坦克等非 Mook 单位。无目标时尝试前方 70px，途中遇实体墙则退至墙前 8px，再向下 80px 找地，无地用角色 Y+2。寻路过滤普通道具、保留电梯；水平范围限于生成点左右各 48px。拆墙只扩大尚未完成的路径，按原定 3.6s 截止重分配剩余路程速度。

普通单位仍通过 `Map.GetUnitsInRange` 查找。可受伤虫类 `AlienMinibossSandWorm` 及派生类改用附近 216px 球形查询，沿现有 `CollisionDamageTarget.FindSkill` 找到指向虫的开放受伤部位，不要求主体登记到 `Map.units`，也不向全局名单补登记。已登记的两种抱脸虫发射虫同样使用部位，避免主体坐标藏在地下或离开范围时漏选。关闭、触发器、失效或护甲保护的部位不参与；存活、敌我、无敌要求保留。对部位中心执行原有 180px／96px、最近距离、视线和向下 80px 找地规则；从中心找地，避免大型头部下缘埋土时探测从地下开始。部位与普通目标共同比较最近落点，吸力和伤害规则不变。

2026-10-22 原菜单核对发现的 Boneworm、BonewormBehind、AlienWorm、LargeAlienWorm 四项遗漏已修复；连同两种 AlienFacehuggerWorm，新 DLL 下六项、双朝向实际释放共 12 条通过，并验证主体逻辑坐标远离头部、全部部位关闭与实墙阻挡。SandWorm 的原生 Damage 直接继承 Unit 空实现，不在本次可受伤虫类补充范围；DrillCarrier 地下状态和 Villager 友方无敌仍单独记录。玩法说法、操作步骤及证据见 [Utility Mod 验证指南](UtilityMod验证指南.md)。

漩涡首次捕获后可跨水片透明间隙继续作用，前提仍在包围范围且无遮挡。每名敌人按对象身份取得稳定的独立相位 `p`，随技能时间 `t` 变化的吸附目标为 `X+16×缩放×sin(p+2.3t)`、`Y+缩放×(62+24×sin(1.618034p+1.7t))`，避免每帧随机抖动或都落到底部。吸力作用于 Mook 活体及完整尸体，排除中酸和失效对象，调用原生 `Knock`：横向目标速度 `clamp(dx×6,-170,170)`、加速度 1200；竖向目标速度 `clamp((目标高度-敌人Y-6)×7,-160,260)`、加速度 2400。重装兵及其尸体横向／竖向分别补偿原生的 20／5 倍衰减；仅活着的重装兵补 0.15s 短眩晕、保留更长眩晕、清理 AI 输入并恢复吸力动量，尸体不改死亡状态。

漩涡周期从生成时刻计时；最后 0.1s 不再追加周期，降低与原生载具约 0.096s 受伤衰减相撞的机会。低帧率不补发全部错过周期。收尾使用当次显示帧，通常索引 24，跳帧时同步跳过；仍在范围且无遮挡的已捕获目标也可受伤。收尾横力远离中心 220、上力 500。

漩涡的往返路线固定先朝世界坐标右侧，与施法朝向无关；贴墙时某段可以缩短为零。生成后只更新横坐标，不随地势、地板破坏或电梯升降改变高度。游戏里表现为经过坑口仍在原高度移动，不能自动追到坑底。

涌泉每目标共享至少 0.12s 的实际命中间隔，最多七击；首次横力远离命中柱中心 70、上力 650，后续冲力为零。同轮按右到左结算，首次击飞取先成功命中的柱中心。同组共享 `SpringDamageState.Acid` 的等级、来源和颜色进度；先检查全组酸池接触，再处理伤害。颜色按共同施法时钟推进，延迟柱继承当前颜色，遍历七柱不会加快渐变。

猎杀向下找地额外使用 `LargeObjects`；其它水平限位和漩涡仍使用严格地形层。普通／巨型电梯保留实体支撑；Boss 顶面支撑不意味着随移动 Boss 附着。涌泉找地忽略箱桶、牢笼和栏杆，但继续检查其后的真实墙体。

涌泉找不到地面不会取消生成：中柱保留角色释放时的 Y，两侧展开时无地则沿用上一步高度。因此水柱可以悬空出现在坑上，不等待角色落地，也不会在之后补做找地。

## 接触、伤害、Boss 与弹丸拦截

### 四技能的像素接触

四技能特效源帧均为 128×128，导出 PNG 与命中蒙版来自同份正式源稿。图集边缘的透明区域不会因为位于画布内就造成伤害。接触余量为世界坐标 **5px**，按缩放换算到源像素。

| 技能 | 普通单位接触方式 | Boss 接触方式 |
| --- | --- | --- |
| 狂潮 | 身体矩形与可见水体像素 | 实际受伤部件矩形与水体像素，兼容代理及非 `Unit` 部件 |
| 猎杀 | `(X,Y+6)` 点与当前独立本体蒙版 | 部件矩形与同一本体蒙版，固定水花不参与伤害 |
| 漩涡 | 首次身体矩形接触，捕获后允许包围范围内的水片间隙 | 每次部件矩形与水体像素 |
| 涌泉 | `(X,Y+6)` 点与柱体像素 | 部件矩形与柱体像素 |

狂潮、猎杀的物件接触，以及 Boss 部件矩形判定，会裁掉水线 `Y+1` 及以下部分，避免 5px 余量伤到支撑底板。普通单位接触和可见性检测按各技能专门逻辑执行，不能把四种技能统一理解为整张画布矩形或同一个圆形范围。

蛞蝓头部的嘴部、上下外壳等碰撞体通过 `DamageRelay.damageGameObject` 指向同一个 `BossSlugFace`，四技能按头部共用命中预算：狂潮 26、鲨鱼跃出 28、漩涡脉冲 3／收尾 9、涌泉每次 4／最多七次。仍经原版代理和 `BossSlugFace.Damage` 扣血，保留死亡、代理保护和原版帧内限制；不强制移动头部。身体 `BossSlugPiece.Damage` 原本为空，不作为可扣血弱点；第二阶段心脏 `BossSlugHeart` 继承 `BossBlockPiece`，沿用该部件路径。

四技能伤害允许敌方尸体参与，由原版碎尸逻辑处理；猎杀潜行恐惧、漩涡自动索敌只找活体，漩涡吸力作用于 Mook 活体及完整尸体，不吸碎肉残肢。普攻水花则仅处理活体。单位路径排除自身、无敌和游戏规则不允许攻击的目标；非单位部件、箱笼和锯齿使用各自资格适配及原生受伤规则，不能把单位的统一过滤条件直接套到所有场景对象。

普通攻击和技能伤害、弹丸屏障均沿用游戏模式的敌我规则：合作闯关不直接伤害队友或拦截其弹丸，对战时其他玩家可受击，其弹丸也可被屏障拦截。不过漩涡自动索敌和鲨鱼潜行恐惧额外排除 `playerNum>=0` 的目标，因此对战玩家能受到实际接触的水攻击，但不会被这两个功能选作目标。场景破坏引发的间接危险仍按原版处理。

通用单位可见性检查在目标距离不足 8px 时直接放行，较远时射线在目标前约 4px 终止；部件检查改为近乎完整射线并跳过接收者本身及同一受伤键。射线忽略单位和伤害代理，漩涡还忽略箱桶／Doodad 等物件；其它技能不统一套用这组忽略规则。因此“无遮挡”指这些代码射线与过滤规则，不是额外的全画幅实体遮挡检测。

### Boss、护甲与原版受伤逻辑

`CollisionDamageTarget` 通过附近真实碰撞体发现受伤对象：解析多层 `DamageRelay` 的最终接收者，并对未登记过的脚本检查原生 `Damage(DamageObject)` 消息接口（含继承的非公开方法）。普通单位继续保留身体判定，明确的单位代理与身体路径共享记录；Block、Doodad 沿用已有地形／物件路径。已知的 `BossPiece`、`BossBlockPiece`、`BossBlockWeapon`、`BossSlugFace`、`BossSatanFloatingHead`、`BossSatanArm` 保留资格与传播预算适配，不再构成目标发现白名单。主体不在 `Map.units` 或主体坐标远离水体时，暴露部件仍可受击。伤害经 `MapController.Damage_Networked` 交给部件原有逻辑，保留护甲、弱点开关、原生网络处理与伤害类型转换，不绕过部件直接扣主体血。`BossPiece.immortal`、方块弱点前置部位存活、武器 `indestructible`、蛞蝓头部死亡和代理保护等限制继续生效；这些非 `Unit` 部件只结算伤害，不套用普通敌人的吸附、上抛或击退。

同一单位的代理部件和常规单位通道共享命中记录；`BossPiece` 按实际 `connectedPieces` 伤害传播范围登记，多个碰撞体或关联部件不会重复扣血，独立弱点保留各自命中机会。猎杀每实例每受伤目标或关联组一次；狂潮普通步兵一次 26，大型单位及非 Block 受伤部件按至少 0.12 秒间隔每次 2、总额最多 26，箱笼一次 26；涌泉七柱共享七次预算；漩涡每周期去重，收尾每目标或关联组一次。代理保护、已销毁代理和已知部件的免疫／关闭状态不消耗暴露弱点的命中机会。未知接收者内部的阶段免疫由原版 `Damage` 决定，命中预算按提交次数记录，不能假定未知私有状态也能提前检查。循环代理不会提交伤害。存活实体 Boss 部件会阻停狂潮，死亡后解除；锯齿明确不阻停，箱桶与牢笼也不阻停。部件不重复参与猎杀的物件伤害。具体开发规则见 [Boss 伤害判定指南](../../../CustomBro-Knowledge/15-Boss伤害判定与攻击覆盖.md)。

代理通道还有一项优先规则：附近查询一旦发现指向某单位的受击代理，本次伤害就以代理为准，即使代理本身没碰到水，身体也不会另行兜底。这保留装甲／弱点保护，但额外偏离身体的代理也可能造成漏伤。这项人工代理复现的实机证据与原生士兵检查见 [修复历史](修复与验证历史.md#2026-10-20-隔墙效果修复与-mcp-受击核对)。

技能攻击对单位、Boss 部件、通过 `FindSkill` 识别的箱桶／牢笼／锯齿默认使用 `Explosion`；毒水对支持原生腐蚀的活敌成功触发时改用 `Acid`，详见下节。狂潮／猎杀对其余地形和普通 Doodad 使用 `Crush`，不能将所有物件统一写成 `Crush`；普攻普通水花使用 `Melee`，蓄力水爆使用 `Explosion`。实际扣血和实际移动均服从目标对应伤害类型的实现，表中冲力不是承诺最终位移距离。

撒旦的两个侧面代理共用浮动头部的命中记录，六条手臂分别独立结算，不把整个 Boss 合并为一个血池。右侧装甲尚存或代理的任一保护碰撞体启用时，该侧头部继续免伤；手臂退到后台、碰撞体关闭时不受击，进入前台并开放碰撞后才可命中。保留头部／手臂的 `Unholy` 免疫和原版阶段逻辑，身体、装甲、眼球等 `BossBlockPiece` 继续走既有路径。开发与现场依据见[撒旦部件修复记录](修复与验证历史.md#2026-10-19-撒旦头部与手臂兼容修复)。

### 水体拦截敌方弹丸

仅**狂潮、漩涡、涌泉**具有水体屏障，鲨鱼没有。屏障只在已显现且仍处有效动画帧时生效；延迟未显现、消散、死亡／禁用清理后或暂停时不拦弹。不是角色全身无敌或无条件防远程攻击，弹丸必须实际接触有效水体。

`WaterProjectileBarrier` 在原版 `Projectile` 各派生类自行声明的 `RunProjectile(float)` 运动／命中处理之前检测：结合弹丸本帧轨迹、水体相对位移和当前像素蒙版做扫掠，避免高速穿透。接触余量为弹丸半径（至少 0.5px）加 5px，而非只看弹丸中心是否落在画布中。

敌对关系取游戏的 `DoesPlayerNumDamage(弹丸玩家,角色玩家)`，友方弹丸放行；只由存活、有效且属于本端的角色执行拦截。命中后归零速度、停用并按网络／本地属性销毁弹丸，**不调用其 `Death`／`MakeEffects`，导弹被水熄灭时不会在角色脚下引爆**。此机制针对进入该 Projectile 运动路径的实体，不会消除已经生成的爆炸、近战或其它非弹丸伤害。

真实墙体会挡住拦弹：水体不能隔墙熄灭另一侧的弹丸；弹丸本帧轨迹若先撞墙，也不会被墙后的水体提前销毁，仍由弹丸原版撞墙逻辑处理。该检查不沿用普通单位不足 8px 时直接放行的捷径，贴身薄墙同样有效。狂潮破坏普通地形／场景物件也补充同类遮挡检查。

## 原生腐蚀与污染来源

污染只属于狂潮、漩涡和涌泉，不传给三叉戟、普通水花、蓄力水爆或鲨鱼。普通／蓄力水花没有持续弹丸屏障；蓄力水爆对可受伤弹丸提交伤害，可能触发其原生爆炸，不能等同于屏障的无爆炸熄灭。

毒水有效命中时，一阶段以 50% 概率、二阶段必定尝试原生腐蚀。`SkillDamageType` 只对存活的 `TestVanDammeAnim`、`canBeCoveredInAcid=true`，且不是 `Alien`／普通 `AlienMosquito` 的目标选用 `DamageType.Acid`；`HellLostSoul` 保留原版特例。不能腐蚀的单位、载具、非 Unit Boss 部件和箱笼／锯齿继续以原本的 `Explosion` 伤害立即结算。单位身体与显式代理共用选择逻辑；代理仍先检查原有技能伤害保护，再核对 `Acid` 路由，酸液不被允许时回退正常技能伤害，不绕过护甲。

酸液经 `Map.KnockAndDamageUnit` 或 `MapController.Damage_Networked` 进入目标原生 `Damage`，由 `CoverInAcid`／`CoverInAcidRPC` 完成变绿、惊慌及 `RunCoveredInAcid`／`Melt` 后续流程。成功选用 `Acid` 时冲力归零、关闭额外 Knock；漩涡对已覆盖酸液的敌人不再施加持续吸力。后续毒水命中已覆盖酸液的活敌继续使用 `Acid`，避免一阶段重新抽到 `Explosion` 后立即打散其骨架。清水和其它原版攻击仍按各自伤害规则处理已中酸液的敌人。

身体入口选用 `Acid` 时同时传 `direction=0`，使酸液按全身附着处理。否则 `MookRiotShield.Damage` 即使收到零冲力的 Acid 也可能按方向阻挡，造成涌泉等路径登记命中却不覆酸。仍经过原生 DamagePolicy、目标 Damage 和代理资格，不强写状态；盾牌脱落等目标自己的原生反应保留。Utility Mod 66 项菜单核对见 [敌人核对表](酸液敌人核对.md)。

已删除旧的 40% 伤害预留、0.3 秒延迟队列及其清理逻辑。酸液不是固定伤害分账：原版可能直接令高血量敌人融化，故普通水技能的 26／36／28 累计扣血上限不能描述腐蚀后的最终死亡效果；各次技能的接触登记和命中次数限制仍保留。酸液附着后由目标自行推进，海王死亡／禁用、水体结束或切换技能不会解除它，也不直接改目标血量或调用 `Melt()` 强制处死。

酸池按 `DoodadAcidPool` 对象身份去重，不按肉眼看到的整片连通池合并；同一大片池若由多个对象组成，可以一次接触升两阶段。酸池不会被消耗，同一池对象可以分别污染多个水体；酸性弹丸则在被第一个接触到的有效水体拦截后销毁。弹丸来源以 `DamageType.Acid` 判定，酸池来源以 `DoodadAcidPool` 类型判定；不限定沙虫类型，也不把普通绿色特效当毒液。污染不会衰减，消散阶段保留已染颜色但不再吸收；渐变源像素按素材路径／技能缓存，单个水体的混色纹理和材质在结束时释放。

敌人死亡后由原版 `CreateSlimeCover` 生成的 `SlimeGroundCover` 也是污染来源，仅接受仍有效、`slimeColor=Green` 且 `damage>0` 的腐蚀残留。通过 `Setup` 后置补丁登记，首次安装时补登记已有实例，接触检查时移除已销毁引用，避免每根水柱每帧扫描全场对象。对象坐标位于地块中心，按 `direction` 将检测点移到外侧 8px 的实际附着面，并沿 16px 宽的面取三个带 4px 半径的接触点；继续使用水体像素、5px 余量与完整墙体遮挡检查。每个残留对象只升级一次，不销毁残留、不阻止其原生腐蚀地形；成片覆盖多个地块可以直接升到二阶段。涌泉沿用整组共享来源和先吸收后伤害的顺序，鲨鱼、未显现和消散水体不参与。

多个水体重叠时，一颗酸弹只由其中一个拦截入口吸收：按水体生成登记的先后顺序检查，第一个通过接触与遮挡检查的水体吸收，后面的水体不会再分到同一颗弹；不是按离弹丸最近的水体分配。若吸收者是涌泉柱，则该次施放的整组水柱一起升级；不会传播到其它次涌泉或其它技能。酸池则取对象 `(X,Y)` 检测点，使用 4px 半径加 5px 接触余量，不按整片酸池外形查询。真实墙体挡在水体与来源之间时不吸收毒液；被遮挡的来源不提前计入污染记录，墙移除后可以正常污染。污染共享不新增柱体、不绕过生成时的墙体探测，伤害与拦弹仍各自检查接触和遮挡。

已经达到二阶段的水体仍会熄灭后续酸弹，只是不再升级；它仍按上述顺序参与拦截，因此可能先消耗酸弹，让重叠的清水或一阶段水体无法获得这颗弹的污染。吸收毒液不会重置水体寿命、延长有效阶段或补回已经用掉的命中次数。

渐变从原始 PNG 解码并缓存像素，避免游戏渲染缓存的 CPU 像素失效造成灰色方块；只混合 RGB、保留每帧原透明度和判定蒙版；素材源稿及配色预览放在 [酸蚀水体](../aseprite-source/03_特殊技能/酸蚀水体/Readme.md)。

## 暂停、清理与联网

四技能的动画、位移和伤害按角色实际 `t` 推进，兼容游戏暂停及 TestMod 单帧调试；本帧未实际重算时间步时不会用旧 `t` 继续播放。普通／蓄力水花按 `Time.deltaTime` 推进，`delta<=0` 不播放、不检测后来进入的目标，动画结束立即销毁。水体屏障在弹丸时间步不推进时也不结算。

角色 `Update()` 每帧先清除时间步就绪标记，由 `SetDeltaTime()` 或击掌加速的 `SetHighFiveBoostDeltaTime()` 在取得正时间步后置位；基类被 TestMod 跳过时，自定义姿态同步和技能推进也停止。这里保留上一帧 `t`，供基类计算移动平台所需的 `lastT`，不能通过每帧先把 `t` 清零实现暂停。单步只放行该帧的自定义更新，击掌加速同样走就绪检查。

角色死亡会清掉其场上四技能，组件禁用同样清理；猎杀另外在失能时立即结束。不能把后者扩大成“任何失能都立刻取消所有其它水技能”。切换技能保留已有水体及其屏障；技能对象随角色建立父子关系，正常生命周期会释放判定登记与镜头引用。已起爆的普通／蓄力水花是独立短期对象，按自身寿命结束，不与技能列表清理混为一谈。

三叉戟只由 `IsMine` 的拥有端通过原版注册 prefab 网络生成，实例外观补丁也处理接收端，不修改共享资源。主动水花伤害、四技能伤害／吸力／物件处理和弹丸拦截只由拥有端执行，伤害继续调用游戏网络接口，避免各端重复结算；HUD 也只更新本玩家角色。上述是当前实现方式，**远程联机实际同步效果尚未验收**，不能仅凭使用网络接口宣称已通过联机验证。

## 动画、头像与 HUD

### 身体、移动和攻击动作

当前身体图集 **1024×640**、武器图集 **1024×288**，基础格 32×32。普通待机 1 帧、跑步 8 帧、跳跃／落地 24 帧，共 33 帧移动动作，使用生成表配对身体和去重后的 24 个手臂／武器姿势。普通跑步帧间隔 0.08 秒；爬梯外观帧间隔 0.1 秒，仅调整视觉，不改梯子移动速度。

直升机软梯运输期间，角色脚本可能被禁用，`Start()` 要等放下角色后才执行。因此在 `Awake()` 的 BroMaker 基类初始化完成、自定义材质已经换好后，立即刷新身体和武器的纹理尺寸缓存并重新计算、上传 UV；`Start()` 再刷新一次。角色首次挂在软梯上显示时即可按当前图集取帧，避免沿用 Rambro 的身体 1024×512／武器旧缓存造成多条横向三叉戟残片。刷新保留当前像素选帧，不改变直升机运动、角色上下梯逻辑或素材。

跳跃按 `abs(xI)>50` 分前进／原地，`yI>20` 为上升，`-55<=yI<=20` 为顶点和初降，`yI<-55` 为快速下落，各组三帧。空中按下键也使用完整身体，避免读取空白蹲姿帧。落地由基类直接衔接待机／跑步，没有另加 0.24 秒落地锁定或强制播放全部落地编辑帧。

站立／蹲姿蓄力起手先过 50ms 初始动作，再保持准备姿态，到 0.5 秒才循环蓝色水流；水流 16 帧循环共 0.533 秒。跑步、跳跃、梯子、滑索的水流循环为 16×40ms=0.64 秒，均不改变 0.5 秒满蓄力阈值。站立投掷收招三阶段为 66／50／66ms。

跑、跳、梯、索攻击把腿部和上半身独立组合，保留地形姿态和移动。竖梯使用独立 18 帧蓄力稿与 5 帧投掷稿，普通爬梯复用恢复持戟姿势，停止移动时保留当前裤腿阶段。滑索攻击优先于一般 Jumping 判断，读取合并的 27 帧正式滑索稿，不能误套空中攻击。

普通蹲持／蹲走的身体和武器来自同一源稿的同一帧，使用相同画布锚点与格号 `64–72`，蹲走每帧 80ms。基类更新后按**最终显示的身体格**同步武器；梯顶切换时即使状态仍为 `ClimbingLadder`、`ducking=false`，已显示的蹲姿也按此配对。不能改为武器帧回退一格或叠加旧 `(2,-1)` 偏移；攻击、近战、翻滚及特殊动作保留各自姿态。

普通爬梯继续调用基类动画与移动逻辑，`useNewLadderClimbingFrames` 和 `useLadderClimbingTransition` 均为 `false`；墙面攀爬的 `useNewKnifeClimbingFrames` 为 `true`，两类入口分别维护。角色不再接触梯子时保留基类已经选出的地面身体和武器，不把它重新覆盖为梯上分层姿态。兼容槽与禁用槽的构建约束见 [素材索引](../aseprite-source/Readme.md#02_地形独立稿)。

近战源稿 8 帧、39×32，四技能施法稿为完整身体帧，播放时不叠加独立手臂；墙面、悬挂、翻滚、死亡、寄生死亡、击掌、秀肌肉等使用相应完整动作。死亡碎块使用独立源稿的头、身、双臂和腿部，金色三叉戟碎块层为空，不额外生成三叉戟碎块。

### 渲染层级

四技能使用 Z=1，位于敌人后、地形前；不是把水体前景盖在敌人之上。普通／蓄力命中水花使用 Z=-12。技能固定释放时的运动方向，人物之后转身不会把已释放特效反向镜像；猎杀潜行左右操作可以改变鲨鱼本身朝向。特效以世界位置更新，父级角色移动不代表技能跟着身体平移。

### 构建、关闭游戏与部署

在本项目目录执行。首次构建先准备本机配置和依赖：

```powershell
Copy-Item ./LocalBuild.example.json ./LocalBuild.json
```

在 `LocalBuild.json` 中设置 `AsepritePath`（可用 PATH 中的 `aseprite`）、`ReferenceDirectory` 和 `DeployDirectories`。默认依赖目录为 `.aquabro-buildrefs`，需自行放入 `Assembly-CSharp.dll`、`0Harmony.dll`、`BroMakerLib.dll`、`RocketLib.dll`、`UnityEngine.dll`、`UnityEngine.CoreModule.dll`、`UnityEngine.PhysicsModule.dll`、`UnityEngine.ImageConversionModule.dll`、`UnityEngine.IMGUIModule.dll` 与 `UnityEngine.TextRenderingModule.dll`。这些依赖与本机配置均被 Git 忽略，不随角色发布。

构建命令：

```powershell
# 仅构建本地资源和 DLL
./BuildAssets.ps1 -SkipDeploy

# 构建并部署至 LocalBuild.json 配置的目录（先关闭游戏）
./BuildAssets.ps1
```

构建依赖 Aseprite 与系统 .NET Framework 3.5 编译器。工具路径优先使用 `-AsepritePath`，其次为 `AQUABRO_ASEPRITE_PATH` 环境变量、本机配置，最后从 PATH 寻找；依赖和部署目录可用 `-ReferenceDirectory`、`-DeployDirectories` 覆盖本机配置。没有配置部署目标时，省略 `-SkipDeploy` 会直接报错，避免将“未部署”误报为成功。

脚本在系统临时目录中生成图集、选帧表、像素蒙版及 DLL，生成和编译全部成功后才替换正式产物，完成后清理本次临时目录。`aquabro-build.rsp` 是不含本机路径的模板，由脚本展开为带引号的临时响应文件，兼容含空格的目录，不直接把模板传给编译器。项目文件统一从 `.aquabro-buildrefs` 引用依赖，也可在被忽略的 `LocalBroforcePath.props` 中覆盖 `AquabroReferencesPath`。输入源稿只用于读取和合成，不会由常规构建重新绘制覆盖。头像／图标导出进程会等待退出，避免未写完就复制。

酸蚀运行时还读取 `skill-tidal-wave-acid-1/2.png`、`skill-maelstrom-acid-1/2.png`、`skill-abyssal-spring-acid-1/2.png`，六张图必须随清水特效及 DLL 一起部署。解码后校验宽度为当前技能帧数×128、高度为 128；缺文件或尺寸错误会使渐变初始化失败，当前没有自动回退清水的保护。常规构建读取六份正式编辑稿，不调用重建工具。

**特效 PNG、图集选帧表和 DLL 内的命中蒙版必须配套更新**。只替换技能 PNG 不会让已经编译的伤害边界自动改变。猎杀还需要同份源稿导出的 `skill-shark-hunt-body.png`、`skill-shark-hunt-water-back.png`、`skill-shark-hunt-water-front.png`，分别用于飞行本体和固定水花。默认部署会复制脚本列出的正式 DLL／PNG 和 `_Mod/Aquabro.json`，并清除对应 `Aquabro.dll.cache`。

默认部署只处理已经存在的目标目录，目录缺失时会跳过，不自动创建。因此脚本输出 `deployment=True` 只表示启用了部署流程；实际同步到哪些目录，应以对应文件存在及源／目标哈希一致为准。

两个游戏目标目录及当前代码快照见 [部署与验证索引](../当前角色实际应用状态.md#当前代码与磁盘部署)。代码或资源变动应同步更新对应机制文档与实际验证记录。部署前终止 Broforce 并确认进程退出（实际进程名已脱敏），再复制 DLL 和配套资源；暂停游戏不能代替这一步。此为操作流程，当前构建脚本不会自动结束游戏。

需要实机验证时可通过本机已有的 Broforce 快捷方式临时启动。完成必要验证、清理临时对象和补丁后，默认终止游戏进程并确认退出，避免持续耗电；用户明确要求保留现场时例外。只修改文档无需启动游戏、构建或部署。
