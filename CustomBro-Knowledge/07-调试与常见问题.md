# 调试与常见问题

来源：[Bro-Maker Wiki - Debugging](https://github.com/Gorzontrok/Bro-Maker/wiki/Debugging) / [FAQ & Common Issues](https://github.com/Gorzontrok/Bro-Maker/wiki/FAQ-%26-Common-Issues)。下列运行时功能依赖已安装的 UMM、BroMaker 和 RocketLib 版本。

## 日志与运行时检查

```csharp
using BroMakerLib.Loggers;
BMLogger.Log("Hello World!");
```

日志可从游戏内 UMM 的 Logs 标签和当前 profile 的 `UMM/Core/Log.txt` 查看。不同机器的数据目录及 profile 名称可能不同；应从 r2modman 当前 Broforce profile 定位，不要照搬其他机器的绝对路径。检查日志目录时，即使时间最新的 `.log` 和 `.trace.log` 都是 0 字节也要查看，并结合 UMM 日志判断启动阶段。

RuntimeUnityEditor 可检查游戏对象、组件和变量。Object Browser 可定位角色组件；Inspector 可查看运行时字段。暂停、改值和恢复后都要确认游戏状态正常，且工具显示的对象属于当前玩家实例。

RocketLib `DrawDebug` 可绘制调试线框；首参 ID 用于复用图形：

```csharp
using RocketLib.Utils;
DrawDebug.DrawLine("myLine", startPosition, endPosition, Color.red, 0.3f);
DrawDebug.DrawRectangle("myRect", corner1, corner2, Color.green, 0.3f);
DrawDebug.DrawCrosshair("myCrosshair", center, 10f, Color.yellow, 0.3f);
```

## 常见问题

| 问题 | 排查方向 |
|---|---|
| 头像或特技图标没生效 | 确认放在 `parameters`，并检查资源路径、图集格式及最终加载的角色定义 |
| `disarmedGunMaterial` 等贴图字段没生效 | 确认它是当前类可写字段，并放在合适的 Awake/Start 阶段；检查字段名与类型 |
| 半透明像素发黑或排序异常 | 检查材质 shader、alpha 导入、sorting layer 和深度设置；没有一个 layer 对所有对象都最稳 |
| 多人选到重复外观变体 | 检查当前 BroMaker 版本的变体去重设置和角色初始化顺序 |
| 死后逻辑仍在运行 | 检查 `acceptedDeath` 等生命周期状态；清理音效、协程和临时对象，并在覆写中正确调用基类 |
| 无敌 tint 留在额外材质 | 确认材质是否注册到 tint 管理，死亡、复活和变身路径是否成对清理 |
| 特技动画被墙跳或爬墙重置 | 检查动画帧计数器是否被多个状态共用；需要时维护特技专用计数器 |
| 近战被其他手势打断 | 检查 `blockGesturesDuringMelee`、`StartMelee`、`CancelMelee` 和该角色实际输入流程 |
| 穿透攻击让 Boss 多次受伤 | 检查碰撞体、代理、本体和关联部件是否映射到同一伤害目标；按目标关系去重，见 [Boss 判定指南](15-Boss伤害判定与攻击覆盖.md#5-去重按受伤关系和伤害节奏设计) |
| 小兵可受伤，Boss 却漏判 | 不要只遍历 `Unit` 或 `DamageRelay.unit`；检查 Boss piece、免疫阶段和完整碰撞/爆炸路径，见[攻击覆盖表](15-Boss伤害判定与攻击覆盖.md#6-每新增攻击都填写覆盖表) |
| JSON 留空后的数值不符合预期 | 解析只赋值提供的字段；核对预制体来源、生命周期赋值顺序和运行时最终值，见 [06 JSON 参考](06-JSON参数与变量参考.md) |
| 枪图或身体图修改后动作异常 | 对照身体帧、持枪手臂和枪图锚点；是否沿用或重绘取决于当前项目美术要求，见 [12 贴图工作流](12-用Aseprite画角色贴图.md) |
| 编译器不支持新语法 | 先确认构建脚本实际使用的编译器版本；旧版 .NET Framework `csc.exe` 常限于 C# 3 语法，目标框架名称本身不能确定编译器版本 |
| 找不到 `RaycastHit` 等 Unity 类型 | 从当前游戏 `Managed` 目录确认定义该类型的模块程序集并添加引用；以程序集核对 API 签名 |
| 部署后子目录资源不见 | 确认部署时递归复制并保留相对路径；知识库脚本模板 `templates/BuildBro.ps1` 已这样处理 |
| 弹射物基类没有 `sprite` 字段 | 检查当前基类组件；需要精灵时可通过 `GetComponent<SpriteSM>()` 获取并缓存，先核对目标版本 API |
| 弹射物不下坠 | 查当前基类重力和 `Update` 调用顺序；自定义重力还要核对时间步长、碰撞检测和联机两端行为 |
| 特技没弹药仍播动画 | 检查弹药消耗与输入/动画启动分别发生在哪个覆写点，按需要在启动前拦截 |
| 游戏里看不到刚部署的 DLL | 确认游戏通过目标 UMM profile 启动、mod 清单引用正确程序集、并检查本次启动日志；部署前关闭游戏 |

## 验证层次

编译成功只证明代码能生成。至少分别确认目标角色已从磁盘加载、关键字段/资源已进入运行时实例、核心交互路径正常。离线单项测试、完整关卡测试、Boss 覆盖和多人网络验证覆盖范围不同；没有实测的范围应保留为待验证。调试时记录游戏版本、BroMaker/RocketLib 版本和测试场景，避免把某一配置下的结果写成通用结论。
