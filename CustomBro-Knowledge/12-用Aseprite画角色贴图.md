# 画角色贴图:用 Aseprite MCP,不要用脚本生成

**结论先行**:画像素画角色贴图走 **Aseprite MCP**(人/AI 直接操作像素级绘图工具),**不要**再写 Python 脚本去"生成"或"改造"贴图。本文记录工具怎么配、怎么用,以及脚本路线为什么被放弃。

---

## 一、为什么放弃脚本路线

2026-09-13 实测。当时为了给一个自定义 bro 做全套 512 帧动作贴图,写了 Python 管线(读原版兰博贴图 → 区域换色 → 贴一个头部零件 → 输出)。**三轮都被否,最后整个工程删除。**

| 做法 | 结果 | 为什么不行 |
|---|---|---|
| 在原版帧上**区域换色**(军绿→金甲、棕裤→翠绿) | ❌ "你这是完全参考了兰博? 我不是让你自己绘制吗" | 轮廓和四肢位置还是别人的。**换了颜色不等于自己画的**,判定标准是骨架 |
| 把设计图的头**贴**到原版帧上 | ❌ "头部经常错位" | 靠算法**检测**头部位置(按人脸/额带连通域找包围盒)必然有偏差;姿态一歪就贴歪 |
| 参数化"腿位变体"(并拢/前跨/后蹬)拼姿势 | ❌ 脚连否三轮 | 亚像素级的形状需求(脚型、黑的占比)靠文字描述对齐不了 |

**根因有两条,都不是工具的错:**

1. **脚本只能"变形"已有像素,画不出新像素。** 像素画的质量全在"这一格该是什么色",这是画师的判断,不是插值算法能给的。区域换色 / 贴图 / 平移拼装都是变形,得到的必然是"别人骨架 + 我的配色"。
2. **需求里最关键的形状信息无法用文字传达到位。** "脚应该只有 1 像素宽" 这一句,可以指小腿 1px、脚掌比小腿宽 1px、或脚掌本身 1px——三种理解画出三种东西。反复猜了三轮才收敛。

**正确做法**:用 Aseprite MCP 直接画,并且**一个动作一张对照图确认**。工具负责"像素操作准",人负责"判断对不对"。

## 二、Aseprite MCP:配置与验证

### 装在哪

| 项 | 值 |
|---|---|
| MCP server 配置 | `~/.claude.json` → `mcpServers.aseprite`(用户级,非仓库级) |
| 实现 | `E:\Study\Python\aseprite-mcp`(Python + uv) |
| Aseprite 本体 | `E:\Program\Aseprite\Aseprite.exe`(1.3.18.1-x64,**非标准安装路径**) |

### 必须配 `ASEPRITE_PATH`

MCP 内部就一行(`aseprite_mcp/core/commands.py`):

```python
cmd = [os.getenv('ASEPRITE_PATH', 'aseprite')] + args
```

Aseprite 不在 PATH 上,不设这个环境变量 → **任何真实操作都报 `[WinError 2] 系统找不到指定的文件`**。

修法:在 `~/.claude.json` 的 `mcpServers.aseprite` 下加 `env`:

```json
"env": { "ASEPRITE_PATH": "E:\\Program\\Aseprite\\Aseprite.exe" }
```

**改完必须重启 Claude Code 才生效**(MCP 进程在启动时就带着环境变量起来了)。

### ⚠️ 验证陷阱:别被 `list_palette_presets` 骗了

`list_palette_presets`、`animation_workflow_guide` 这类工具返回的是**硬编码数据,根本不调用 Aseprite**。所以:

- 环境变量没配好时,它们**照样返回正常结果**;
- 拿它们做连通性测试 → 误判成"MCP 是好的"。

**正确的验证**:调一个**碰真实文件**的工具,比如 `create_canvas`。或者直接模拟 MCP 的执行方式:

```bash
export ASEPRITE_PATH="E:\\Program\\Aseprite\\Aseprite.exe"
"$ASEPRITE_PATH" --batch --script probe.lua        # probe.lua 里建 sprite 并 saveAs
```

`--batch` 模式下 Lua 里 `print()` 是唯一回传通道;**退出码为 0 不代表逻辑成功**,要 print 出中间结果。

## 三、画角色的正确流程(核心)

### 第 1 步:先把"角色规格"定死,存成文件

**这是整件事成败的关键。** 直接说"帮我画个海王"然后就一个动作一个动作要 —— 每画一个动作,颜色、比例、头发样子都会飘,最后得到一堆长得不一样的"海王"。

规格要包含三样:

1. **长相**:逐部位描述(头发/脸/上身/腰/下身/脚),描述到"什么形状、什么颜色、几像素宽"。
2. **配色表**:固定色值,明确"只能用这几个"。像素画一旦颜色漂了,整套就不像一套。
3. **硬规则**:帧尺寸、角色在帧内的位置、描边规则、禁止抗锯齿/半透明。

### 第 2 步:先画"站立帧",确认了再往下

后面所有动作都从这一帧改四肢。**站立帧不对,越画越歪。** 画完导出放大图给人看,点头了再继续。

### 第 3 步:一个动作一个动作要,每张都确认

```
站立 → 走 → 跑 → 跳 → 蹲 → 近战 → 特技 → 翻滚 → 死亡 → 爬墙/滑索/爬梯……
```

**一次只做一个动作。绝对不要说"把 512 帧全画完"。**

### 第 4 步:提意见要"说成什么样",不要只说"不对"

| 无效反馈 | 有效反馈 |
|---|---|
| "脚不像人样" | "小腿应该只有 1 像素宽,脚是纯绿的,不要黑鞋底" |
| "头不对" | "头发要盖住额头,金额带压在最上面一行" |

**拿不准的时候,让它画两个方案放一起挑** —— 比反复用文字描述快得多。这是实测最有效的一条:**形状类需求要给候选图,不要给形容词。**

## 四、开箱即用的规格模板

新开对话画角色时,把这段整个贴进去再改:

```text
我要用 aseprite 画一个像素小人,做 Broforce 的自定义角色。

【角色长相】
- (逐部位描述:头发 / 额头 / 脸 / 上身 / 腰 / 下身 / 脚)
- 每个部位说清形状和颜色

【固定配色,只能用这几个】
#RRGGBB 用途
#RRGGBB 用途
...

【规则】
- 每个动作画在 32x32 一帧里,角色脚底对齐第 27 行、水平居中
- 轮廓一圈纯黑 1 像素,不要抗锯齿,不要半透明
- 只能出现上面列的颜色

请先做两件事:
1. 按上面规格把"站立帧"画出来,存成 <角色名>.aseprite
2. 导出放大后的图给我看

画完先给我看,我确认了再往下。不要一次画很多。
```

## 五、和 Broforce 接轨

画完要进游戏时,导出尺寸和帧布局必须对(详见 [11 文档](11-导出官方贴图与资源包.md)):

| 贴图 | 尺寸 | 栅格 |
|---|---|---|
| 身体 | 1024×512 | 32 列 × 16 行 × 32×32 = 512 帧 |
| 枪 | 1024×64 | 32 列 × 2 行 × 32×32 |
| 头像 | 128×64 | 4 格 32×64 |
| 特技图标 | 16×16 | 单张 |

**帧号 = 行号 × 32 + 列号**,每个帧号播什么动作见 11 文档的对照表。

> 官方角色的全套动作图已解包在 `Broforce_src/GameAssets/hero/`(95 张)。**画之前先打开对应角色看一眼**——动作怎么画、帧怎么排,看真人比读文档快。

## 六、这套工具还有什么用

除了画新图,批量处理类活很适合交给它(比手写脚本省事):

- 把某角色整版图逐帧过一遍,生成带帧号标注的接触表
- `render_onion_skin` 查动作帧之间连不连贯
- `compare_frames` 比两帧差异,确认改动真的生效
- `color_stats` 查用了多少种颜色(像素画配色纪律)
- `export_spritesheet` / `export_frame` 导出与放大自查
- `run_lua_script` 是兜底出口:上面没覆盖的操作,直接写 Lua
