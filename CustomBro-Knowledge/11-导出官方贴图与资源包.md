# 导出官方贴图与资源包(assetbundle 解包)

做自定义 bro 时,最有用的一手参考就是**官方角色自己的整版图** —— 动作怎么画、帧怎么排、枪手怎么握,打开看一眼比在游戏里逐帧截图快十倍。本文记录怎么把它们导出来。

**已导出的成品在** `Broforce_src/GameAssets/`(598 张,含清单 `index.csv`),重导方法见那边的 README。
**工具在** `CustomBro-Knowledge/templates/ExportGameSprites.py`。

---

## 一、素材藏在哪

Broforce 是 Unity 游戏,官方美术全部在这些 **asset bundle** 里:

```
<游戏>\Broforce_beta_Data\StreamingAssets\
    sharedtextures.assetbundle      ← 29 MB,全部角色/道具/特效贴图
    sharedsounds.assetbundle        ← 143 MB,全部音效
    scenesmain / scenshared / ...   ← 关卡场景
    cutscenes.assetbundle           ← 过场
    levels.assetbundle              ← 关卡
    networkobjects.assetbundle      ← 联机对象
```

**别在错的地方找**:`Broforce_beta_Data\` 根目录下那些 `resources.assets`、`sharedassets0.assets`、`level0` 是引擎自身的,不含角色贴图。

## 二、怎么导

```bash
python -m pip install UnityPy
python CustomBro-Knowledge/templates/ExportGameSprites.py
```

核心就三行 —— 遍历 bundle 里的 `Texture2D` 对象还原成 PNG:

```python
import UnityPy
env = UnityPy.load(ASSETBUNDLE)
for obj in env.objects:
    if obj.type.name == 'Texture2D':
        d = obj.read()
        d.image.save(d.m_Name + '.png')
```

脚本额外做了三件必要的事:

1. **按尺寸分类落盘**(bundle 里混着大量视差图、特效、UI,不筛会导出几百张没用的 4K 图)。
2. **强制重名去重** —— 见下。
3. 生成 `index.csv` 清单。

## 三、两个实际会踩的坑

### 坑 1:属性叫 `m_Name`,不是 `name`

UnityPy 1.25 的 `Texture2D` 没有 `name` 属性,写 `d.name` 直接 `AttributeError`。

### 坑 2:同名同尺寸的贴图会静默互相覆盖

包里存在**名字和尺寸都一样、但内容不同**的贴图。用 `名字_宽x高.png` 直接落盘,后一张会覆盖前一张,而且**不报错**。实测:不加去重会丢 14 张(icon 丢 10、cutscene 丢 4);`hero/`(角色图)恰好没有重名,所以这个坑容易一直发现不了。

脚本的处理:同一个 `stem` 第二次出现时加 `__dup1`、`__dup2` 后缀。**验收标准是 `index.csv` 行数 == 落盘文件数**,对不上就是又有重名了。

## 四、帧布局规格(拿到图之后必须知道)

导出的图**直接就是游戏能读的整版图**,尺寸本身就编码了帧布局,不需要额外切分信息:

| 贴图 | 尺寸 | 栅格 | 帧尺寸 | 帧数 |
|---|---|---|---|---|
| 身体图 | 1024×512 | 32 列 × 16 行 | 32×32 | 512 |
| 枪图 | 1024×64 | 32 列 × 2 行 | 32×32 | 64 |
| 头像 | 128×64 | 4 格 | 32×64 | 4 |
| 过场 | 256×256 | 单张 | — | 1 |
| 特技图标 | 16×16 | 单张 | — | 1 |

**帧号 = 行号 × 32 + 列号。**

> 两个常见误解(实测纠正):
> - **枪图不是 16 帧 64×64**,是 32 列 × 2 行、每格 32×32。按 64×64 切会把两个姿势塞进一格。
> - **头像不是 2 帧 64×64**,是 4 格 32×64,且内容落在每格的 row 27~63(上半是空的)。

## 五、帧号 → 动作

权威来源是这张**带白色数字标号**的图(数字标在每个动作块的起始帧):

```
E:\Study\C#\Bro-Maker\images\Example Spritesheets\rambroAnimLabeled.png
```

它和 `RAMBRO` 的身体图逐像素一致,只是多了标号。同目录还有 `rambroGunLabeled.png`、`rambroAnimLabeledTrimmed.png`。

> **别用相邻帧相似度自动切动作。** 同一个走路循环内部的帧间差异,和跨动作之间的差异是同一量级 —— 实测 IoU 阈值 0.55 切出 66 段、0.88 切出 246 段,全被切碎,切不出动作边界。

常用帧号速查:

| 帧号 | 动作 | 帧号 | 动作 |
|---|---|---|---|
| 0–3 | 站立 idle | 96–103 | 冲刺 |
| 4–5 | 死亡 | 107–124 | 滑索 |
| 6–9 | 蹲 | 145–152 | 特技投掷 |
| 17–22 | 击掌 | 160–173 | 爬梯 |
| 25–31 | 近战 | 177–183 | 空中近战 |
| 32–39 | 走 | 203–214 | 烟囱翻越 |
| 40–47 | 跑 | 235–242 | 胸口爆裂（寄生死亡） |
| 51–63 | 翻滚 | 352–375 | 地面 flex |
| 64–75 | 跳跃 | 466–469 | `FlexAirJump` 起身 |
| 76–95 | 刀爬墙 | | |

另外 Broforce 的 Hero 类里有一批 **`useNew*Frames` 开关**(`useNewDuckingFrames`、`useNewThrowingFrames`、`useNewLadderClimbingFrames` …… 见 06 文档),同一动作在图上准备了两套帧,由这些开关决定用哪套。改帧的时候要确认游戏当前用的是哪一套。

`FlexAirJump` 不是一段连续图集：起跳使用 402–406，随后前空翻使用 330–341，向下砸地使用 434–437，落地起身使用 466–469。BroMaker 的 `BetterAnimation=true` 会开启 `hasNewAirFlexFrames`，不能只看这些格子平时很少出现就判定为废帧。

> 图集中未启用的动作格可以保持全透明,但必须保留画布尺寸和固定格号；不能根据“游戏里很少见”直接判断为废帧。`BetterAnimation`、能力强化、口袋特技和外部 API 都可能启用低频动作。判断方法、TonyBrotana 反例及 Aquabro 已关闭的爬梯帧见 [12 文档：未启用的动作格能否留空](12-用Aseprite画角色贴图.md#未启用的动作格能否留空)。

## 六、导出结果概览

`Broforce_src/GameAssets/`(598 张,0 失败;`index.csv` 是完整清单):

| 目录 | 数量 | 内容 |
|---|---|---|
| `hero/` | 317 | 角色动作图(95 张 1024×512)、枪图(94 张 1024×64)、BOSS、杂兵 |
| `avatar/` | 30 | 128×64 |
| `cutscene/` | 96 | 256×256 |
| `icon/` | 155 | 16×16 |

95 张身体图里 **64 张是可玩角色**,含各种变体形态(金属/无臂/带血/张嘴)。

保真度已验证:`RAMBO_anim_1024x512.png` 与 Bro-Maker wiki 的 `rambroAnim.png` **逐像素完全一致**;`RAMBRO_gun_anim_1024x64.png` 与 `rambroGun.png` 同样一致。不是有损转换,可以放心当像素级参考。

**注意** `avatar/`、`icon/` 是按尺寸硬筛的,里面混着非角色素材(锯片、栅栏、蛆虫等)。找特定角色请用 `index.csv` 按名字筛。

## 七、合规

导出的都是官方版权素材。**自己参考、改色、做 mod 底图没问题;把它打包进对外分发的 mod 就是分发别人的版权资源。** `Broforce_src/GameAssets/` 的图片已加进仓库 `.gitignore`,只有 README 和 `index.csv` 会提交。
